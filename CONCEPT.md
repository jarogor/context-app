# CONCEPT.md — Каркас, приложение и плагины

Стратегическая концепция проекта: что такое каркас, что такое приложение и что
такое плагины, как они связаны и как называются. Это **единственный источник
истины по этой концепции**: `ROADMAP.md` описывает направление и приоритеты,
`openspec/specs/` — текущее поведение, этот файл — устройство, на которое
опираются и направление, и поведение. Концепцию нельзя терять при правках и
нельзя расходиться с ней в коде, именах и спеках.

## Три уровня

```
+--------------------------------------------------------------------------+
| КАРКАС (framework)                                                       |
|   пустой обезличенный фундамент: на нём строят ЛЮБОЕ приложение          |
|   (книжный инструмент, музыкальный плеер, чат)                           |
|   - базовый функционал                                                   |
|   - служебные инструменты                                                |
|   - спецификации                                                         |
|   - права плагинов                                                       |
|   - SDK для авторов плагинов                                             |
+--------------------------------------------------------------------------+
| Приложение строится "по законам каркаса и спецификаций"                  |
v
+--------------------------------------------------------------------------+
| ПРИЛОЖЕНИЕ (application) — реализация каркаса под конкретную задачу       |
|   в нашем случае — «Контекст» (инструмент исследователя книг)            |
|   - пространство книг                                                    |
|   - пространство заметок                                                 |
|   - рабочее место (вкладки, композиции)                                  |
+--------------------------------------------------------------------------+
| Приложение расширяется плагинами                                         |
v
+--------------------------------------------------------------------------+
| ПЛАГИНЫ (plugins) — расширяют приложение и обновляются по частям          |
|   типы:  с фронтендом  /  без фронтенда                                  |
|   права: объявлены заранее                                              |
+--------------------------------------------------------------------------+
```

Каркас **не является** приложением и не является его частью: это то, на чём
приложение стоит. Каркас пустой — он не знает ни о книгах, ни о заметках, ни о
форматах. Чтобы построить на нём другое приложение, берут каркас, его
спецификации и SDK и пишут собственные плагины.

## Каркас

Обезличенный фундамент. Не содержит предметной области (книг, заметок, чтения).

- **Базовый функционал** — то, что нужно любому приложению независимо от задачи:
  контракт плагинов, выполнение плагинов в песочнице WASM, маршрутизация
  операций, служебное состояние.
- **Служебные инструменты** — обезличенные сервисы, поставляемые вместе с
  каркасом: настройки, журнал диагностики, установка и учёт плагинов, обновление
  приложения. Они не знают о задаче приложения.
- **Спецификации** — то, чем описывают приложение и его плагины: манифест
  плагина, декларативный интерфейс (`ui-schema`), служебные файлы состояния,
  реестры, версии контракта.
- **Права плагинов** — модель разрешений. Плагин заранее объявляет, что ему
  разрешено (какие host-функции и возможности), и получает только объявленное.
  Ориентир — разрешения мобильных приложений: набор известен заранее, плагин
  запрашивает его декларативно, система выдаёт только разрешённое. Усложнять не
  нужно, но принцип «сначала объявил — потом получил» соблюдается.
- **SDK** — инструменты для авторов плагинов: привязки host-функций, конструктор
  декларативного интерфейса, каркас типовых задач (например, версионированное
  хранилище и миграции).

Каркас поставляется как код и спецификации; приложение его использует, но не
переписывает.

## Приложение

**Приложение — это то, что реализовано по законам каркаса и его спецификаций.**
В нашем случае приложение — «Контекст», инструмент исследователя книг. Именно
приложение является **рабочим местом**: местом, где исследователь собирает воедино
книги и заметки и ради которого строится всё остальное.

Приложение содержит предметные части:

- **пространство книг** — каталог, поиск, организация книг;
- **пространство заметок** — наборы заметок к книгам, поиск, импорт/экспорт;
- **пространство рабочих мест** — список рабочих мест, поиск, импорт/экспорт.
- **рабочее место** — композиция вкладок, где книга и её заметки встречаются.

Приложение расширяется плагинами, а не меняет каркас.

## Плагины

Плагин — самостоятельная единица расширения, поставляемая отдельным артефактом
(манифест + модуль), которую можно устанавливать, отключать и **обновлять по
частям** отдельно от приложения. Плагины бывают как минимум двух типов.

### Тип: с фронтендом

Плагин несёт собственный интерфейс и исполняет его в изолированной области.
Такой плагин нужен там, где содержимое нельзя нарисовать общими средствами
приложения. В «Контексте» это **плагины форматов чтения**: EPUB, FB2, PDF, DjVu.
Плагин формата владеет рисованием книги и обменом с приложением; управление и
оформление страницы остаются у приложения.

### Тип: без фронтенда

Плагин предоставляет данные и поведение через операции и события, а интерфейс
рисует само приложение общими средствами (декларативный интерфейс
`ui-schema`). Это обычные предметные плагины: источники книг, хранилище заметок,
расширения.

### Права плагинов

Независимо от типа плагин объявляет права в манифесте и получает только их.
Права — это разрешения на host-функции каркаса и на предоставление
возможностей другим плагинам. Модель прав закладывается каркасом заранее.

### Обновление по частям

Плагин живёт отдельно от приложения и обновляется отдельной поставкой. Поэтому
приложение не должно требовать пересборки из-за одного плагина, а плагины не
должны быть связаны друг с другом общей сборкой: связь плагинов — только через
объявленные права и возможности, а не через общий код.

Граница обновления проходит по уровню плагина. **Ядро** — приложение и
каркасные плагины (`level: framework`) — обновляется целиком одним пакетом из
одного источника: каркасные плагины и приложение связаны контрактом, и
подменять их поодиночке нельзя. **Прикладные плагины** (`level: application`) —
источники книг, заметки, форматы чтения, расширения — обновляются по отдельности
через стор из произвольных источников.

## Термины

- **Каркас** — обезличенный фундамент, на котором строят приложения: базовый
  функционал, служебные инструменты, спецификации, права, SDK.
- **Приложение** — реализация под конкретную задачу, построенная по законам
  каркаса и его спецификаций. В нашем случае — «Контекст».
- **Рабочее место** — здесь возможны два значения, их нужно различать:
  - в широком смысле — само приложение, место сборки книги и заметок;
  - в узком смысле — именованная **композиция вкладок** внутри приложения
    (`workspaces.json`), которых может быть много.
- **Плагин** — самостоятельная единица расширения приложения: манифест + модуль,
  устанавливается, отключается и обновляется по частям.
- **Плагин с фронтендом** — плагин, несущий свой интерфейс (в «Контексте» — плагин
  формата чтения).
- **Плагин без фронтенда** — плагин, предоставляющий данные и поведение, интерфейс
  рисует приложение.
- **Права плагина** — объявленный в манифесте набор разрешений, которые плагин
  получает от каркаса.
