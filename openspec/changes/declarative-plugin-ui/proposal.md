## Why

Сейчас интерфейс части приложения поставляют автономные frontend-плагины
(`plugins/*`, iframe, `kind: "ui"`, отдельные сборки в `public/plugins/`). Каждый
такой плагин рисует свой интерфейс, поэтому единая дизайн-система не может
обеспечить единство и контролируемое качество оформления. Плагины в перспективе
будут писать сторонние авторы, а значит нельзя давать им полную свободу в UI:
разрешённое нужно объявлять явно и обеспечивать версионированным контрактом.

Направление уже частично заложено: `packages/ui-schema` содержит скелет
декларативного дерева UI, где событие узла отображается в идентификатор действия,
а не в колбек. Нужно зафиксировать модель целиком и переработать приложение под
неё.

## What Changes

- **BREAKING** Автономные frontend-плагины перестают существовать: убираются
  `kind: "ui"`, iframe-загрузка и отдельная сборка frontend-плагинов. UI первых
  плагинов (уведомления, настройки, стор, библиотека) переносится в приложение.
- Плагины описывают интерфейс **декларативно** деревом `ui-schema`; рендерит хост
  компонентами `@texture/ui`. Плагин не задаёт вёрстку и стили.
- Вводятся **пространства интерфейса** (точки расширения) со стабильными
  идентификаторами. Хост объявляет, в какие пространства и какие элементы/свойства
  разрешено добавлять; плагин вносит элементы только туда.
- Взаимодействие — **интенты, а не колбекi**: событие узла ссылается на
  идентификатор действия; хост доставляет плагину сообщение с действием и
  значениями, плагин владеет состоянием и возвращает обновлённую декларацию. Поток
  унидирекциональный, вызовы плагина сериализуются хостом.
- Вводится **SDK** для описания UI в плагинах (типизированные компоненты,
  пространства) и версия схемы (`ui-schema`) для согласованности при развитии.
- Набор элементов начинается с **минимума по необходимости**, расширяется позже.

## Capabilities

### New Capabilities

- `plugin-ui`: декларативный UI плагинов — пространства с идентификаторами,
  разрешённые элементы, интенты вместо колбеков, версионирование схемы и SDK.

### Modified Capabilities

- `plugin-system`: автономные UI-плагины больше не загружаются; UI предоставляется
  декларативно и рендерится хостом.
- `design-system`: хост — единственный рендерер интерфейса; он рисует декларации
  плагинов компонентами дизайн-системы, без iframe-приложений.
- `app-shell`: оболочка рендерит декларативный UI и встроенные поверхности вместо
  переключения между автономными frontend-плагинами.

## Impact

- Ядро: `src-tauri/src/plugin/` (`PluginKind::Ui`, загрузка UI-плагинов), возможно
  host-функции обмена UI-сообщениями; новые команды для интентов.
- Фронтенд: `src/App.svelte` и `src/lib/PluginFrame.svelte` (удаление),
  `packages/ui-schema` (схема/версии), `packages/ui` (рендерер и компоненты),
  `plugins/*` (перенос UI в приложение, удаление).
- Скрипты: `scripts/build-frontend-plugins.sh` (удаление), `package.json`
  workspaces, e2e-фикстуры `packages/testing`.
- Спеки: обновление `notifications`, `settings`, `plugin-store`, `library-ui` по
  мере переноса их UI (в рамках этого изменения).
- Документация: `README.md`, `AGENTS.md`, `_docs/plugin-architecture.md`,
  `_docs/structure.md`.
