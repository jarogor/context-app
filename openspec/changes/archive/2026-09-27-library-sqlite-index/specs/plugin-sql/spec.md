## Purpose

Generic SQL host API для плагинов: плагин исполняет SQL и читает строки результата
через opaque host-функции, а ядро предоставляет изолированное SQLite-хранилище на
активную библиотеку, не интерпретируя модель данных плагина.

## ADDED Requirements

### Requirement: Opaque SQL host API

Приложение SHALL предоставлять плагинам host-функции исполнения SQL:
`sql_execute(sql, params)` для изменяющих и произвольных выражений и
`sql_query(sql, params)` для чтения строк. Аргумент `params` SHALL быть
JSON-массивом скалярных значений (`null`, число, строка), подставляемых в
запрос; `sql_query` SHALL возвращать JSON-массив объектов «имя столбца →
значение». Ядро SHALL NOT интерпретировать SQL, схему или предметный смысл
данных: оно лишь исполняет запрос в хранилище, привязанном к активной сессии.

#### Scenario: Плагин читает строки

- **WHEN** плагин вызывает `sql_query` с SELECT-запросом и параметрами
- **THEN** приложение возвращает JSON-массив строк с именами столбцов, не разбирая предметный смысл запроса и результата

#### Scenario: Плагин изменяет данные

- **WHEN** плагин вызывает `sql_execute` с запросом создания таблицы или вставки
- **THEN** приложение исполняет запрос в хранилище сессии и возвращает признак успеха

#### Scenario: Ошибочный SQL

- **WHEN** плагин передаёт некорректный SQL
- **THEN** приложение возвращает диагностируемую ошибку вызова, не нарушая работу сессии и остальных плагинов

### Requirement: Изолированное хранилище на библиотеку

SQL-хранилище SHALL открываться на активную сессию библиотеки и SHALL быть
привязано к каноническому корню библиотеки и идентификатору провайдера. Файл
базы SHALL располагаться вне директории самой библиотеки — в служебной области
приложения. Разные библиотеки и разные провайдеры SHALL иметь раздельные
хранилища; при отсутствии активной сессии SQL-вызов SHALL завершаться ошибкой.

#### Scenario: Раздельные хранилища библиотек

- **WHEN** в двух разных библиотеках плагин создаёт одноимённую таблицу
- **THEN** данные каждой библиотеки сохраняются в собственном файле базы и не смешиваются

#### Scenario: Внешняя библиотека не изменяется

- **WHEN** плагин пишет в SQL-хранилище внешней библиотеки
- **THEN** запись выполняется вне директории библиотеки, не создавая и не изменяя там файлов

#### Scenario: Провайдеры не делят индекс

- **WHEN** одну директорию открывают разные провайдеры
- **THEN** каждый провайдер получает раздельное хранилище, привязанное к своему идентификатору
