## Why

Source-плагины хранят построенный каталог как JSON в служебном состоянии
(`library-state.json`, `calibre-state.json`) и при каждом открытии перечитывают
содержимое всех файлов библиотеки, чтобы восстановить название, авторов и
обложку. На реальной библиотеке это занимает десятки секунд и делает повторное
открытие неотличимым от первого сканирования. Нужен реляционный локальный индекс,
который позволяет обнаруживать только изменённые файлы и обновлять их точечно.
WASM-плагины изолированы (без WASI FS), поэтому SQLite может предоставить только
ядро — через общий opaque-контракт.

## What Changes

- Ядро предоставляет плагинам **generic SQL host API** поверх SQLite:
  `sql_execute(sql, params)` и `sql_query(sql, params)`. Соединение открывается
  на активную библиотеку, схему, миграции и запросы определяет сам плагин;
  ядро не интерпретирует модель данных.
- Файл SQLite-базы хранится **вне директории библиотеки** — в служебной области
  приложения и привязан к каноническому корню библиотеки и провайдеру, что
  сохраняет read-only-гарантию внешнего источника.
- Host-функция `fs_list_dir` дополнительно возвращает для файлов **размер и
  время изменения** — чтобы source-плагин обнаруживал изменения без чтения
  содержимого.
- Generic-плагин `library` и `library-calibre` переводят своё persisted-состояние
  с JSON на SQLite и синхронизируют индекс **инкрементально**: неизменённые
  файлы не перечитываются, читаются только новые и изменённые, удалённые
  исключаются. Стабильный идентификатор книги — относительный путь.
- **BREAKING** формат служебного состояния source-плагинов меняется (JSON →
  SQLite); существующая JSON-запись несовместима и при открытии заменяется
  полной перестройкой индекса. Внешняя библиотека при этом не изменяется.

## Capabilities

### New Capabilities

- `plugin-sql`: generic SQL host API для плагинов — исполнение SQL и запросы со
  строками результата, изолированное хранилище на активную библиотеку,
  ограничения и диагностика.

### Modified Capabilities

- `library-index-cache`: локальный индекс source-плагина хранится в SQLite через
  SQL host API и актуализируется инкрементально по размеру и времени изменения
  файлов; перечитываются только новые и изменённые книги.
- `plugin-system`: host-функция `fs_list_dir` возвращает для файловых записей
  размер и время изменения (mtime) в дополнение к имени и типу.

## Impact

- Ядро: `src-tauri/Cargo.toml` (новый крейт `rusqlite` с bundled-SQLite),
  `src-tauri/src/plugin/contract.rs` (имена host-функций),
  `src-tauri/src/plugin/runtime.rs` (регистрация `sql_execute`/`sql_query`,
  соединение на сессию, `fs_list_dir` с метаданными),
  `src-tauri/src/plugin/session.rs` (корень SQLite-хранилища).
- Source-плагины: `src-wasm-plugins/library/` и `src-wasm-plugins/library-calibre/`
  (схема, миграции, инкрементальный скан, отказ от JSON-состояния).
- Документация: `_docs/plugin-contract.md`, `_docs/plugin-architecture.md`,
  `_docs/library-index.md`, `AGENTS.md` (при необходимости).
