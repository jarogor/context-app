## Context

`AppState::new` получает `storage_root` для базовых плагинов от функции
`base_storage_root()` в `src-tauri/src/lib.rs`:

```rust
fn base_storage_root() -> PathBuf {
    crate::paths::dev_data_dir().join(BASE_PLUGINS_DIR_NAME)
}
```

`paths::dev_data_dir()` считается от `env!("CARGO_MANIFEST_DIR")` — абсолютного
пути рабочей копии, вшитого в бинарь при компиляции. Поэтому и debug, и release
читают `dev_data/base-plugins` репозитория. Спека `app-state` требует иного:
`base-plugins/*.json` — часть каталога состояния приложения, который в release
живёт в каталоге данных приложения (`constants::resolve_app_state_root`). Страница
«Информация» уже показывает `app-state/base-plugins` (`AppInfo::build`), то есть
код хранилища расходится и со спекой, и с собственной диагностикой.

## Goals / Non-Goals

**Goals:**
- Состояние базовых плагинов лежит рядом с прочим служебным состоянием и следует
  развилке сборки dev/release.
- Release-сборка не читает и не пишет dev-данные рабочей копии.

**Non-Goals:**
- Миграция прежнего `dev_data/base-plugins` в пользовательские данные: в release
  собственного состояния не было, а в разработке путь меняется предсказуемо.
- Изменение формата файлов состояния и контракта плагинов.

## Decisions

### D1. Корень хранилища вычисляется от каталога состояния

Заменить `base_storage_root()` на `app_state_root.join(BASE_PLUGINS_DIR_NAME)`.
`app_state_root` уже проходит развилку по сборке (`constants.rs`), поэтому
отдельной ветки для release не требуется, а путь совпадает с тем, что публикует
`AppInfo`. Альтернатива — повторить `cfg(debug_assertions)` в новой функции —
дублирует развилку и снова рискует разойтись со спекой.

### D2. Существующее dev-состояние переезжает вместе с каталогом

В разработке состояние окажется в `dev_data/app-state/base-plugins`; прежний
`dev_data/base-plugins` больше не читается. Отдельного шага миграции не делаем:
каталог принадлежит разработке, а в release-путь никто не писал.

## Risks / Trade-offs

- [В разработке «пропадут» прежние настройки/заметки] → Данные разработки;
  при необходимости переносятся вручную копированием в
  `dev_data/app-state/base-plugins`. Автоматический перенос усложнил бы код ради
  разового случая.
- [Release-сборка впервые начнёт писать состояние базовых плагинов] → Это и есть
  целевое поведение: своё состояние в каталоге данных приложения.

## Migration Plan

Правка одной строки в `lib.rs` и тест. Порядок: изменить вычисление корня, обновить
тест расположения, прогнать `cargo test`, `clippy`, `fmt`.
