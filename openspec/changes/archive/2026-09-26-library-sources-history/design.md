## Context

См. `proposal.md` — Why. Состояние, важное для подхода:

- Frontend `library-ui` жёстко задаёт `plugin = 'library'` при открытии
  (`plugins/library-ui/src/bridge.ts`); ядро (`commands/plugin_operation.rs`)
  лишь конфигурирует сессию этим плагином. Операция `probe` у source-плагина есть
  (`src-wasm-plugins/library/src/scanner.rs`), но ядром не используется.
- Сканер `library` читает только «автор/книга» и подтягивает метаданные из EPUB;
  история (`recent-libraries.json`) хранится в состоянии плагина, операции
  `recent_list`/`recent_remember`/`recent_forget`, признак `available` там
  выставляется всегда `true`.
- Портируемый режим (`mode: portable`) обрабатывает тот же плагин `library`
  (создание/импорт в writable-режиме).
- Активация/деактивация плагинов отсутствует (только install/uninstall) — это
  отдельный change.

## Goals / Non-Goals

**Goals:**

- Generic-источник: рекурсивный обход, каждый файл поддерживаемого формата —
  отдельная книга (название из имени файла, без автора и обложки).
- Calibre — отдельный source-плагин с текущей раскладкой «автор/книга» + EPUB/OPF.
- Ядро выбирает source-плагин по `probe` с приоритетом.
- Общая история библиотек у ядра: провайдер + доступность + фильтрация по
  наличию провайдера, скрытые записи сохраняются.
- UI истории с маркером провайдера и признаком доступности.

**Non-Goals:**

- Автоматическое извлечение метаданных (название/автор/год) из содержимого —
  следующий шаг.
- Чтение `metadata.db` Calibre.
- Активация/деактивация плагинов (отдельный change).
- Обложки у generic-источника.

## Decisions

### 1. Generic-источник — текущий плагин `library`

Сканер переписывается: рекурсивный обход (с ограничением глубины и пропуском
скрытых/служебных папок), **каждый файл книги = отдельная книга**. `title` — имя
файла без расширения, `authors` — пусто, обложки нет. `id` книги — относительный
путь файла. Портируемый режим (создание/импорт/чтение) остаётся в этом же
плагине. Ранний выход из обхода — как только найдена хотя бы одна книга для
`probe`.

### 2. Calibre — отдельный плагин `calibre`

Новый `src-wasm-plugins/calibre/` переносит текущую логику: раскладка
«<автор>/<книга>», метаданные из EPUB/OPF, `probe` подтверждает только Calibre-
раскладку. Read-only; `metadata.db` не читается.

### 3. Выбор источника по `probe` с приоритетом

`probe` расширяется ответом `{ supported: bool, priority: number }`. Ядро при
открытии внешней директории опрашивает все загруженные source-плагины и выбирает
подтвердивший с **наибольшим приоритетом**; при равенстве — первый по порядку
загрузки. Calibre возвращает более высокий приоритет, generic — низкий (чтобы не
перехватывать Calibre-директории). Портируемая структура распознаётся ядром
раньше внешних источников. Альтернатива с полем `priority` в манифесте и правкой
`plugin-system` отклонена: приоритет — свойство самого протокола источника.

### 4. История библиотек у ядра

Новый модуль ядра `library_history` хранит записи `{ path, provider, added_at }`
в app-level файле (dev — `dev_data/app-state/`, prod — каталог данных
приложения). Команды:

- `library_history_list` — записи, отфильтрованные по провайдерам, которые
  сейчас доступны (загруженные source-плагины), с вычисленным признаком
  доступности пути (существование директории);
- `library_history_remember(path, provider)`;
- `library_history_forget(path)`.

Записи недоступных провайдеров сохраняются, но не выдаются; при возвращении
провайдера снова видны. Обоснование выбора ядра, а не плагина: нужен доступ к
списку доступных source-плагинов и к файловой системе для проверки пути — оба
знания есть у ядра. Операции `recent_*` из source-плагинов удаляются.

### 5. Открытие внешней библиотеки без жёсткого имени плагина

Ядро предоставляет операцию открытия по пути, которая сама выбирает source-плагин
(п. 3), конфигурирует сессию, записывает запись истории `(path, provider)` и
возвращает выбранного провайдера вместе с каталогом. `library-ui` больше не
передаёт `plugin = 'library'` для внешних источников; для последующих операций
использует выбранного провайдера. Портируемое открытие сохраняет текущий режим.

### 6. UI истории

`library-ui` показывает записи истории с названием провайдера и иконкой
доступности; недоступные — с пометкой. Выбор записи открывает библиотеку
провайдером записи. Записи отсутствующих провайдеров не показываются.

## Risks / Trade-offs

- [Рекурсивный probe/скан дорогой] → ограничение глубины и ранний выход; скрытые папки пропускаются.
- [Generic перехватывает портируемые/Calibre директории] → приоритет probe и проверка портируемой структуры ядром до внешних источников.
- [Ядро владеет историей — расширение домена ядра] → это app-level UX-состояние, не формат источника; альтернатива (базовый плагин) не может проверять ФС и знать набор активных source-плагинов.
- [Изменение фронтенд↔ядро API] → старые `recent_*` удаляются вместе с использованием; открытие по пути добавляет один маршрут.
- [Проверка доступности пути в ядре] → только чтение существования директории, без записи.

## Migration Plan

1. Переписать сканер `library` на generic; `probe` отдаёт приоритет.
2. Вынести Calibre в `src-wasm-plugins/calibre/`; добавить в workspace и сборочный скрипт.
3. Ввести выбор источника по `probe` с приоритетом и открытие по пути в ядре.
4. Добавить модуль и команды истории; убрать `recent_*` из плагинов.
5. Обновить `library-ui` (мост, история, открытие по пути).
6. Откат: изменения фронтенд + WASM + небольшой модуль ядра; вернуть из git.
