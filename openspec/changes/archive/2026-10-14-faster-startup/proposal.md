## Why

Приложение при запуске несколько секунд показывает экран «Загрузка…», хотя на
старте не делает ничего содержательного: библиотека ещё не открыта, книг нет,
заметки не нужны. Измерения в текущей (debug) сборке показывают две главные
причины: на критическом пути старта компилируются WASM-плагины, которые для
первого кадра не нужны (плагины чтения — ~3.4 c, при этом ни одна книга не
открыта), а тяжёлая инициализация удерживает общий `Mutex<AppState>`, из-за чего
любой параллельный запрос ждёт своей очереди и интерфейс «замирает то там то сям».
Чем больше станет библиотек и заметок, тем хуже будет старт, если грузить их
заранее. Нужно грузить на старте только то, что действительно нужно для первого
кадра, а всё остальное — по действию пользователя, не блокируя друг друга.

## What Changes

- **Убрать с критического пути старта всё, что не нужно первому кадру:**
  - список форматов читалки (`reader_formats`) перестаёт запрашиваться при старте
    и запрашивается только когда пользователь открывает библиотеку/книгу;
  - реестр заметок (`list_all_sets`) перестаёт читаться на стадии начальной
    загрузки и грузится при открытии раздела «Заметки» (с индикатором), как и
    прочие ленивые данные.
- **Компиляция базовых плагинов перекрывается с загрузкой окна:** инициализация
  базовых плагинов запускается в фоне при старте приложения (в `setup`) и идёт
  параллельно с загрузкой webview, а не начинается по первому запросу интерфейса.
- **Тяжёлая инициализация не держит общий замок:** сборка app-level runtime и
  runtime чтения выполняются вне общего `Mutex<AppState>`; лёгкие команды (реестр
  рабочих мест и т.п.) не встают в очередь за компиляцией.
- **Прогрев source-плагинов на старте сужается/убирается:** сейчас он компилирует
  source-плагины при запуске параллельно с запросом форматов читалки и они
  конкурируют за CPU; прогрев остаётся только там, где он действительно нужен, и
  не дублирует другую работу.
- **Гигиена кэша компиляции WASM:** кэш ограничивается и чистится, чтобы старые
  записи не копились неограниченно (сейчас 245 записей, ~520 МБ).
- **Инструменты измерения:** добавляются цели сборки/запуска в release-режиме
  (`make release`, `make run-release`), чтобы можно было сравнить скорость старта
  одной и той же функциональности в debug и release.

### Modified Capabilities

- `app-lifecycle`: старт грузит только данные, нужные первому кадру; тяжёлая
  инициализация плагинов перекрывается с загрузкой окна и не находится на
  критическом пути экрана загрузки.
- `app-shell`: реестр заметок больше не читается на стадии начальной загрузки;
  раздел «Заметки» загружает реестр при открытии и показывает индикатор.
- `notes-library`: данные реестра загружаются при открытии раздела, а не на
  стадии начальной загрузки; реестр по-прежнему обновляется при изменении
  хранилища без перезапуска.
- `library-ui`: список поддерживаемых форматов читалки определяется при показе
  поверхности библиотеки/открытии книги, а не при запуске приложения.
- `plugin-system`: app-level runtime и runtime чтения инициализируются вне общего
  замка состояния; компиляция базовых плагинов идёт в фоне при запуске; кэш
  компиляции WASM ограничен и очищается.

## Impact

- Сборка и запуск: `Makefile` — новые цели `release` (release-сборка десктоп-
  приложения) и `run-release` (собрать без упаковки и запустить бинарь).
- Ядро: `src-tauri/src/lib.rs` (фоновый старт инициализации базовых плагинов и
  runtime чтения в `setup`), `src-tauri/src/plugin/app_state.rs` и
  `src-tauri/src/plugin/shared_runtime.rs` (готовность `app_host`/`reader` без
  удержания общего замка), `src-tauri/src/plugin/warmup.rs` (один прогрев runtime
  чтения, разделяемый с командами чтения),
  `src-tauri/src/plugin/wasm_cache.rs` (ограничение и очистка кэша),
  команды ядра, читающие базовые плагины.
- Оболочка: `src/features/lifecycle/bootstrap.ts` (убрать реестр заметок из
  бутстрапа), `src/features/library/LibraryPage.svelte` (запрос форматов только
  при показе библиотеки/открытии книги), `src/app/App.svelte` (загрузка реестра
  заметок при открытии раздела «Заметки»).
- Спеки: `app-lifecycle`, `app-shell`, `notes-library`, `library-ui`,
  `plugin-system`.
- Не меняется: контракт плагинов, модель заметок, формат состояния, поведение
  команд, кроме времени готовности и момента запроса ленивых данных.

## Startup Measurements (task 1.2)

Замер — по логам `[startup]` (переменная `TEXTURE_STARTUP_TIMING`), время от
старта процесса; оба бинаря собраны из одного кода, кэш компиляции WASM общий.

| Сборка  | setup   | первый кадр | фон: плагины чтения | фон: базовые плагины |
|---------|---------|-------------|---------------------|----------------------|
| debug   | 0.23 c  | **0.69 c**  | 7.47 c              | 8.44 c               |
| release | 0.25 c  | **0.52 c**  | 0.29 c              | 0.29–0.31 c          |

- Первый кадр **отвязан от компиляции WASM** в обеих сборках: в debug экран
  загрузки сменяется интерфейсом на 0.69 c, хотя фоновая компиляция идёт до
  8.4 c. До изменения эти же секунды удерживали критический путь (бутстрап ждал
  `app_host()`, `LibraryPage` безусловно ждала `reader_formats()`).
- Release заметно быстрее: и первый кадр (0.52 c против 0.69 c), и фоновая
  компиляция (доли секунды против секунд в debug). В debug скомпилированные
  wasmtime модули не переиспользуются кэшем (ключ кэша зависит от артефакта
  хоста), поэтому фоновая компиляция повторяется при каждом запуске — это и есть
  причина, по которой dev ощутимо медленнее.
