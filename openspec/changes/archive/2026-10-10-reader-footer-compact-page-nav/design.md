## Context

См. `proposal.md` — Why. Текущее устройство нижней панели чтения
(`src/features/reader/ReaderFooter.svelte`, рисуется `WorkplaceArea.svelte` из
снимка активной вкладки):

```
[ масштаб ] [ тема области чтения ]        [ ‹ 11 из 123 | [№] | ›  42% ▓▓▓░░ ]
```

- Номер страницы — отдельный `<span data-testid="reader-page">`, рядом `span`
  «из N», а затем отдельное `<input aria-label="Перейти к странице">` с локальным
  `pageInput`.
- `pageInput` живёт сквозной привязкой: `ReaderFooter` `bind:pageInput` ↔
  `WorkplaceArea.pageInput` ↔ команда `ReaderPage.gotoFooterPage(value)`.
  Значение поля не сбрасывается на текущую страницу, поэтому расходится с
  отображаемым номером.
- Ряд навигации — обычный `flex` без признаков `shrink-0`/`whitespace-nowrap`,
  поэтому при узком окне надписи переносятся и блок «съезжает» по вертикали.
- `Progress` и процентная цифра показываются всегда, полоса не адаптируется.
- Единая точка «узкое окно» в проекте — `max-[899px]` (панели заметок и
  уведомлений, `matchMedia('(max-width: 899px)')` в `WorkplaceArea`).

Навигация по страницам доступна только для страничных форматов
(`workplace && workplacePages && workplacePage !== null`); текстовые форматы
блока не показывают.

## Goals / Non-Goals

**Goals:**
- Одна точка ввода номера — само поле текущей страницы; без дублирующего поля.
- Поле всегда отражает фактическую текущую страницу и следует за листанием.
- Компактный и неизменный блок навигации: элементы не переносятся при сужении.
- Прогресс на узком окне — только цифра, без полосы; по единой точке `899px`.

**Non-Goals:**
- Поведение при сильном уменьшении окна (когда места заведомо не хватает) —
  решается отдельным изменением.
- Не меняется масштаб, тема области чтения, контракты плагинов рабочего места и
  снимок нижней панели (кроме формы команды перехода).
- Не меняется логика границ страниц (`page-state.ts`).

## Decisions

### 1. Текущая страница — поле ввода перехода (всегда)

`ReaderFooter` рисует поле номера текущей страницы на месте бывшего `span`.
Поле — контролируемое значение снимка (`workplacePage`), а не отдельное
состояние:

- Отображаемое значение — текущая страница; при листании и после перехода оно
  обновляется из снимка, поэтому расхождения «в поле одно, в навигации другое»
  больше нет.
- Пользователь правит локальный черновик (буфер) при вводе; по `Enter` (и по
  потере фокуса) черновик разбирается и передаётся командой перехода. Нечисловой
  и пустой ввод игнорируется, поле возвращается к текущей странице.
- Подпись — `aria-label="Текущая страница"`; рядом пометка `«/ N»` вместо
  `«из N»`.

Поле строится из `Input` дизайн-системы с компактным классом ширины, а не нативным
`<input>`: единый вид и токены.

**Альтернатива:** оставить `span` с номером и поле-дублёр. Отклонено — это и есть
текущий дефект (двойная точка ввода, рассинхрон значений).

### 2. Переход как команда со значением страницы

Сквозная привязка `pageInput` удаляется:

- `ReaderPage`: `gotoFooterPage(value: string)` заменяется командой перехода по
  **числу** (разбор и границы — на стороне нижней панели/`clampPage`).
- `WorkplaceArea`: состояние `pageInput` и `goToPage(value: string)` убираются;
  `ReaderFooter` получает колбэк `onGoToPage(page: number)` и вызывает его сам.
- `ReaderFooter`: черновик ввода — локальное состояние компонента; наружу уходит
  уже разобранное число.

**Альтернатива:** держать `pageInput` в `WorkplaceArea` и синхронизировать его
со снимком. Отклонено — панель уже владеет снимком и отрисовкой, лишнее состояние
на уровне рабочего места усложняет синхронизацию.

### 3. Прогресс: полоса скрывается по единой точке `899px`

Процентная цифра остаётся всегда; `Progress` скрывается классом
`max-[899px]:hidden`. Точка — та же, что у боковых панелей (`max-[899px]`),
отдельного значения не вводится.

**Альтернатива:** условный рендер через `matchMedia`. Отклонено — CSS-правило уже
использует единую точку, а `display: none` так же убирает полосу из раскладки без
JS-состояния и рассинхрона.

### 4. Неизменный блок навигации

Кнопки перехода и поле обрамляются контейнером без переноса
(`flex items-center gap-1 shrink-0 whitespace-nowrap`), поле имеет фиксированную
компактную ширину и центрирование. Надписи `«/ N»` и процент получают
`whitespace-nowrap`, поэтому «съезжание» по вертикали исчезает в рабочем диапазоне
ширин. Выход за пределы очень узкого окна в это изменение не входит (Non-Goals).

**Альтернатива:** адаптивно перестраивать блок (скрывать кнопки, менять порядок).
Отклонено — пользователь явно просил убрать адаптивность блока; сильное сужение
обсуждается отдельно.

## Risks / Trade-offs

- [Изменение семантики поля ломает существующие e2e-запросы] → Обновить
  `tests/e2e/pdf-reader.spec.ts` (лейбл `Перейти к странице` → `Текущая страница`,
  текст `из N` → `/ N`, идентификатор номера страницы) и компонентные тесты
  `ReaderFooter.test.ts`, `WorkplaceArea.test.ts`; идентификатор `reader-pages`
  сохранить.
- [Скрытая полоса остаётся в DOM] → Скрытие через `display: none` убирает её из
  раскладки; тест проверяет видимость (`toBeHidden`), а не отсутствие в DOM.
- [Черновик поля рассинхронизируется со снимком при быстром листании] → Значение
  поля выводится из текущей страницы, черновик живёт только во время правки и
  сбрасывается к текущей странице после перехода/потери фокуса.

## Migration Plan

Данные и форматы хранения не затрагиваются: меняется только вёрстка и форма
команды перехода внутри фронтенда. Откат — возврат отдельного поля ввода и
восстановление сквозного `pageInput`.

## Open Questions

Нет. Поведение при сильном уменьшении окна намеренно вынесено за рамки (Non-Goals)
и решается отдельным изменением.
