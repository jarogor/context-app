## Why

UI настроек сейчас показывает секцию как сырой JSON, что непонятно обычному пользователю. Настройкам нужны человекочитаемое название и редактируемое значение по типу, поэтому декларация секций должна описывать поля (название, тип, значение по умолчанию), а не только значения по умолчанию.

## What Changes

- Расширить декларацию секции настроек: вместо `defaults` секция описывает поля `fields` с `key`, `title`, `type`, необязательными `description`, `default` и `options` (для выбора).
- Поддержать типы полей: `boolean` (флажок), `string` (текст), `number` (число), `select` (выбор из вариантов).
- Возвращать в операции `register`/`list` метаданные полей вместе с текущими значениями, чтобы UI мог построить форму.
- Переделать UI настроек: вместо JSON-редактора — форма с названием и типизированным контролом для каждого поля и кнопкой сохранения секции.
- Обновить декларации настроек приложения и плагина уведомлений на новый формат.

## Capabilities

### New Capabilities

Нет новых capabilities.

### Modified Capabilities

- `settings`: секции декларируют типизированные поля с названиями, операции возвращают метаданные полей, UI отображает человекочитаемую форму вместо сырого JSON.

## Impact

- WASM: `src-wasm-plugins/settings/` (модели, реестр, хранилище, операции; тесты).
- Frontend: `plugins/settings-ui/` (типы, страница с формой).
- Ядро: декларация настроек приложения в `plugin/app_host.rs`.
- Сборка: `scripts/build-wasm-plugins.sh` (декларация уведомлений).
- Документация и OpenSpec-спека `settings`.
