## Context

- См. `proposal.md` — Why. Фронтенд — npm workspace: корень приложения
  `src/` + члены `packages/*`.
- Точки входа фиксированы конфигами: `index.html` → `/src/main.ts`, `main.ts` →
  `./Root.svelte`, `Root.svelte` → `./App.svelte`. Файлы `main.ts` и `index.html`
  остаются на месте; переезжают `App.svelte`, `Root.svelte`, `app.css`.
- `vitest.config.ts` включает тесты как `src/**/*.test.ts`, компонентные тесты
  лежат рядом с компонентами; `tsconfig.app.json` включает `src/**`.
  `playwright.config.ts` работает через dev-сервер и код `src/` не импортирует —
  эти конфиги не меняются.
- Единственный упорядоченный участок — `src/lib/reader/` (чтение и заметки). Его
  сохраняем как вложенную папку фичи `reader`.
- `src/app.css` содержит `@source '../packages/ui/src'` — относительный путь от
  `src/` к пакету дизайн-системы.

## Goals / Non-Goals

**Goals:**
- Разложить код по назначению: `src/app`, `src/shared`, `src/features/<домен>`.
- Сохранить внешнее поведение, публичные API модулей и состав тестов.
- Оставить конфигурации сборки максимально нетронутыми (без path-алиасов).

**Non-Goals:**
- Не менять поведение, Tauri-контракты, данные и `packages/*`.
- Не переписывать содержимое модулей (только пути и импорты).
- Не менять `index.html` и `src/main.ts` (точки входа Vite).
- Не вводить алиасы импортов (`$lib`/`$app`).

## Decisions

### 1. Три уровня: app, shared, features
Код делится на слой каркаса (`src/app`), общий слой (`src/shared`) и доменные
фичи (`src/features/<домен>`). Домены взяты из карты функций и `ROADMAP.md`:
`appearance`, `library`, `settings`, `notifications`, `store`, `workplace`,
`reader`, `notes`, `lifecycle`. Каждая фича содержит свои компоненты, логику и
тесты. Альтернатива «слоями (components/services/state)» отклонена: она не
отражает домены и расходится с vertical-slice из правил проекта.

### 2. `reader` забирает страницы чтения и заметок
Папка `reader/` (парсеры/утилиты чтения) остаётся вложенной в
`features/reader/`; туда же переезжают презентационные области чтения
(`ReaderPage.svelte`, `BookReader.svelte`, `WorkplaceContent.svelte`,
`viewer-bundle.ts`). `WorkplaceContent` связан одновременно с `reader` и `notes`,
но по смыслу это область содержимого книги, поэтому живёт в `reader`.
`NotesPanel.svelte` и клиент `notes.ts` — в `features/notes/`.

### 3. Клиент области — в фиче с самой областью
Клиенты базовых плагинов (`library.ts`, `settings.ts`, `notifications.ts`,
`plugin-store.ts`) переезжают в одну фичу с использующей их областью, а не
в общий слой. Так «фича = область + клиент + тест» остаётся цельной.

### 4. Каркас и бутстрап — в `src/app`
`Root.svelte`, `App.svelte`, `app.css` образуют слой приложения. Бутстрап
(`bootstrap.ts`) зависит от клиентов почти всех фич; чтобы не разрывать каркас,
он живёт в подпапке `src/features/lifecycle/` вместе с `BootstrapLoading/
BootstrapError`. Импорт из `App.svelte` при этом становится `./features/lifecycle/bootstrap`.

### 5. Без path-алиасов
Импорты остаются относительными: алиасы потребовали бы правок
`vite.config.ts`/`tsconfig*.json`/`vitest.config.ts` и риск рассинхрона. Правка
относительных путей механическая. Альтернатива (алиасы `$shared`, `$features`)
отложена.

### 6. Ссылки на пути в документации и спеках
Активные `openspec/specs/` не ссылаются на `src/`, поэтому спеки не меняются
(изменение объявлено `skip_specs: true`). Архивные изменения не трогаем — это
исторические записи. Актуализируется `_docs/structure.md` (техсправка
разработчика).

### 7. Мусор шаблона удаляется
`src/lib/Counter.svelte` и `src/assets/{svelte.svg,vite.svg,hero.png}` не
используются (`grep` по коду пуст), удаляются без замены.

## Risks / Trade-offs

- [Риск: пропущенный относительный импорт после переезда] → После переноса —
  `npm run check` (svelte-check + tsc) и `npm test`; ошибки компиляции укажут
  на непоправленные пути.
- [Риск: путь `@source` в `app.css` разойдётся с новым положением] → Пересчёт
  относительного пути (`src/app/app.css` → `../../packages/ui/src`) и проверка
  полной сборкой `npm run build`.
- [Риск: визуальная регрессия из-за Tailwind `@source`] → `make e2e`
  (Playwright, визуальные снапшоты) подтверждает прежний кадр.
- [Trade-off: `features/lifecycle` — не домен в `ROADMAP`, а техническая
  группировка бутстрапа] → Название описательное; при появлении новых
  каркасных модулей папка расширяется.
- [Риск: компонентные тесты ищут `.svelte` относительным путём] → Пути в тестах
  правятся в том же переносе, что и компоненты.
