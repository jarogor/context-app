## Why

Рабочее место не должно знать, откуда у него книга. Сейчас вкладка адресует
книгу идентификатором в каталоге активной библиотеки, а чтение идёт через сессию
её source-плагина. Из-за этого восстановленная при запуске вкладка падает с
состоянием «библиотека этой книги не открыта», произвольный файл с диска открыть
нельзя, а библиотека навязывается пользователю поперёк его выбора.

Требования пользователя: рабочее место открывает книги произвольно; если книга не
найдена — не ломаться и предложить указать файл; никаких действий втихую; заметки
привязаны к книге, а не к вкладке. Это архитектурная правка: модель вложения
вкладки, способ чтения, поток переуказания файла и ключ заметок.

## What Changes

- Вложение вкладки — **путь к файлу книги**; рабочее место не хранит и не знает
  библиотечный идентификатор. Библиотека при открытии книги лишь поставляет путь.
- Появляется **отдельный runtime чтения** в ядре: он собирает source- и рабочие
  плагины без привязки к открытой библиотеке и читает файл по пути. Песочница на
  время чтения сужается до директории файла, source-плагин получает имя файла.
- Новые IPC-команды чтения по пути (`reader_formats`, `reader_plugin_for_format`,
  `reader_viewer`, `reader_content`, `reader_open_external`, `reader_book_chunk`,
  `reader_forget_book`); прежние команды рабочего места по книге библиотеки
  удаляются.
- Формат книги определяется по расширению пути; состояние «библиотека не открыта»
  и автоматическое открытие библиотеки удаляются полностью.
- Недоступная вкладка показывает заглушку с действиями «Указать файл» (выбор
  любого файла на диске) и «Убрать вкладку», сохраняя состояние чтения.
- Ключ заметок — путь к файлу: заметки и подсветки общие для всех вкладок одной
  книги независимо от библиотеки.
- Библиотечный UI при открытии книги передаёт рабочему месту абсолютный путь
  файла (корень активной библиотеки плюс относительный путь книги).

### Modified Capabilities

- `reader`: чтение книги по вложению-пути через runtime, не зависящий от
  открытой библиотеки.
- `reading-workspace`: вложение вкладки — путь к файлу, произвольный файл с диска,
  переуказание любого файла, пустое состояние без библиотеки.
- `workspace-manager`: вкладка добавляется при открытии книги из библиотеки или
  файла с диска.
- `library-ui`: действие «Открыть в рабочем месте» передаёт абсолютный путь файла.

## Impact

- Ядро Rust: `src-tauri/src/plugin/app_state.rs` (ленивый `ReaderConfig`, чтение,
  открытие и порции по пути, песочница на директорию файла),
  `src-tauri/src/commands/reader.rs` (новые команды), удалён
  `src-tauri/src/commands/workplace.rs`, проводка в `lib.rs` / `commands/mod.rs` /
  `plugin/mod.rs`; `src-tauri/src/workspace_state.rs` хранит `path` (с алиасом
  `book_id` для миграции).
- Фронтенд-оболочка: `src/lib/workplace.ts` (вложение-путь), `src/lib/reader/`
  (API по пути), `src/lib/ReaderPage.svelte`, `src/lib/WorkplaceArea.svelte`,
  `src/lib/WorkplaceTabs.svelte`, `src/lib/WorkplaceContent.svelte`,
  `src/lib/notes.ts` (ключ книги — путь), `src/App.svelte` (открытие и
  переуказание через системный диалог).
- Библиотечный UI: `plugins/library-ui/src/BookPage.svelte`,
  `plugins/library-ui/src/bridge.ts` (абсолютный путь, форматы по `reader_formats`).
- Мок-мост и тесты: `packages/testing/src/fixtures.ts`, модульные и браузерные
  сценарии рабочего места и чтения.
- Документация: `ROADMAP.md` (журнал решений), `_docs/reader.md`, `_docs/notes-editor.md`.
