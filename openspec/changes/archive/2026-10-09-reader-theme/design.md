## Context

Мотивация — в `proposal.md`. Существенные для подхода детали текущего состояния:

- **Оформление — шов дизайн-системы.** `packages/ui` владеет реестром палитр
  (`palettes.ts`: `gruvbox`, `mist`), а сторона (светлая/тёмная) выбирается
  атрибутом `data-theme` на корне документа (`theme.ts`). Палитры заданы
  токенами CSS в `tokens.css`. Значения `appearance.theme`/`appearance.palette`
  читает ядро (`AppPluginHost::theme_preference`/`theme_palette`), применяет
  оболочка на бутстрапе (`bootstrap.ts → applyAppearance`), изменение приходит
  событием `settings:changed` в `App.svelte`.
- **Две независимые реализации области содержимого.** EPUB рисует встроенный
  `BookReader.svelte`: документ собирает `reader/reader-document.ts` как
  автономный `srcdoc` с инлайновым CSS, где фон и текст захардкожены
  (`#fff` / `#1f2937`). PDF рисует плагин `workplace-pdf` в песочнице
  (`viewer/index.html`) со своими захардкоженными цветами фона (`#525659`) и
  заметок (`NOTE_COLORS`). Оба документа изолированы: они не наследуют CSS
  оболочки, поэтому значения темы нужно доставлять в них явно.
- **Обмен с плагином — opaque-сообщения** (`workplace-protocol.ts`,
  `WorkplaceContent.svelte`): хост шлёт `open`/`zoom`/`tool`/`notes`, плагин
  отвечает событиями. Расширение протокола — единственный способ передать теме
  плагину.
- **Цвета заметок** живут в `notes/model.ts` (`NOTE_COLOR_SWATCHES` — акценты
  для образцов, `NOTE_COLOR_HIGHLIGHTS` — мягкие тона для страницы и метки
  списка) и продублированы в плагине PDF. Рассчитаны на белый фон страницы.

## Goals / Non-Goals

**Goals:**

- Тема области чтения — независимая от темы интерфейса ось, переиспользующая
  реестр палитр; первая версия — стороны `light`/`dark`, расширяемая на будущее.
- Единое оформление области чтения для обеих реализаций (встроенное чтение и
  плагин) из одного источника значений.
- Адаптация цветов заметок к стороне темы области чтения.
- Быстрый переключатель в нижней панели читалки + полное поле в настройках;
  сохранение, применение на бутстрапе и мгновенная смена без сброса позиции.
- Никаких правок кода компонентов/плагина при смене набора значений (тема —
  атрибут + токены).

**Non-Goals:**

- Новые палитры (сепия, «ночная» и т.п.) — реестр переиспользуется как есть;
  вводится только ось стороны темы области чтения.
- Хранение темы области чтения в состоянии вкладки или рабочего места: это
  общая настройка приложения.
- Изменение формата хранения заметок: цвет остаётся стабильным идентификатором,
  меняется только тон отрисовки.

## Decisions

### 1. Тема области чтения — отдельная ось поверх общего реестра палитр

Значение настройки `reader.theme` в секции `app.general`; допустимые значения —
стороны палитры (`light`/`dark`), по умолчанию `light`. Тема интерфейса
(`appearance.theme`) и тема области чтения независимы: интерфейс может быть
тёмным при светлой книге и наоборот.

*Почему:* пользователю нужна гибкость (модель JetBrains: тема IDE и тема
редактора раздельно); «тёмная как у всех» слишком контрастна. *Почему тот же
реестр:* один источник наборов токенов; будущие палитры автоматически доступны
обеим областям. *Альтернатива — своя палитра только для чтения:* плодит вторую
систему оформления и расходится с дизайн-системой.

### 2. Единый источник значений темы области чтения в дизайн-системе

Новый чистый модуль `packages/ui/src/reader-theme.ts` экспортирует:

- тип `ReaderThemeId = 'light' | 'dark'` и нормализацию;
- тип токенов области чтения: фон, цвет текста, вторичный текст, ссылки;
- мягкие тона заметок для стороны темы;
- функцию `readerThemeTokens(palette, id)`, возвращающую конкретные значения.

Модуль — единственный источник значений для обеих песочниц. Встроенное чтение
встраивает его значения в CSS документа книги; хост передаёт их плагину
сообщением. `data-reader-theme` на корне области содержимого выбирает нужный
набор правил — смена значений не требует правок кода.

*Почему не одни CSS-токены:* документы EPUB и PDF изолированы и не наследуют CSS
оболочки; значения всё равно нужно доставлять явно, а два независимых источника
(CSS + TS) неизбежно разъедутся. *Альтернатива — прокидывать CSS-переменные через
`postMessage` как готовую строку:* то же, но менее типобезопасно и не тестируемо
в отрыве от DOM.

### 3. Расширение протокола области содержимого сообщением темы

В `workplace-protocol.ts` добавляется сообщение хост→плагин
`{ type: 'reader-theme', value: { id, tokens } }` (по образцу `zoom`/`tool`).
Плагин применяет его: ставит `data-reader-theme` на корень своего документа и
раскладывает токены в CSS-переменные; цвета заметок берутся из переданного
набора. Сообщение отправляется при готовности плагина и при каждой смене темы.

*Почему токены, а не только `id`:* плагин изолирован и не может импортировать
дизайн-систему; резолв значений остаётся в одном месте. *Почему сообщением, а не
манифестом:* тема меняется в рантайме, а плагин может её не знать.

### 4. Применение в EPUB без перезагрузки содержимого

`reader-document.ts` собирает стиль сразу для обеих сторон, ключуя правила по
`html[data-reader-theme='light'|'dark']` (и заметки — там же). `BookReader`
при смене темы ставит `doc.documentElement.dataset.readerTheme` вместо
пересборки `srcdoc`. Это сохраняет позицию прокрутки и уже построенную разметку
заметок (требование «без перезагрузки содержимого и без сброса позиции»).

*Альтернатива — пересборка документа при смене темы:* сбрасывает позицию и
подсветки, дороже. *Альтернатива — держать оба документа:* лишний рендер книги.

### 5. Переключатель в нижней панели + поле в настройках; общий путь записи

Нижняя панель читалки (`ReaderFooter.svelte`) получает компактный переключатель
темы области чтения рядом с масштабом; полный выбор — поле `reader.theme` в
секции `app.general`. Оба пути пишут одно значение через `saveSettingsValues` и
читают событие `settings:changed` — состояние согласовано, как у темы
интерфейса. Ядро читает значение командой `reader_theme`.

### 6. Тема области чтения — общая для всех вкладок

Значение живёт в состоянии приложения (в `App.svelte`/`Root.svelte`, из
`bootstrap.ts`), а не во вкладке, и передаётся в каждую `ReaderPage`. Смена темы
применяется ко всем открытым вкладкам сразу.

### 7. Метка заметки в списке следует теме области чтения

`noteMarkerColor` начинает возвращать тон выбранной темы области чтения, чтобы
цвет заметки совпадал «на странице и в списке» при любой теме. Тона подбираются
читаемыми и на светлой, и на тёмной области (умеренно насыщенные).

### 8. Страница PDF перекрашивается в цвета темы

PDF рисуется в `<canvas>` через pdf.js: видимые глифы и графика — пиксели растра
(текстовый слой pdf.js прозрачный и служит только выделению), поэтому CSS-цветом
текст не перекрасить. В тёмной теме растр страницы перекрашивается в **цвета
темы**: тёмный текст уходит в цвет текста темы (`ink`), белая бумага — в цвет
фона темы (`paper`). Цели задаёт дизайн-система по палитре (`readerPageColors`):
у Gruvbox бумага тёплая (`#33302d`), у Mist — холодная (`#282d31`), поэтому
страница сохраняет оттенок темы и не уходит в нейтральный чёрный; бумага при
этом темнее прежней светлой, но заметно светлее нейтрального чёрного. Текст
мягкий (`#d5c4a1`/`#ccd2d6`), поэтому контраст ниже чистого белого. Каждый канал
движется линейно между «чёрный → ink» и «белый → paper» с сохранением
отклонения канала от яркости, поэтому фото и цветная графика темнеют, но
остаются узнаваемыми. Светлая тема растр не трогает.

*Почему не CSS-фильтр `invert`/`hue-rotate`:* он инвертирует и оттенок, из-за
чего фотографии и цветные схемы становятся ложными. *Почему не нейтральный
тёмно-серый:* почти-чёрный фон (#181818) слишком контрастен и безлик; цвета
палитры дают мягче и в тон теме. *Цена:* обход пикселей видимых страниц при
отрисовке. Подсветки и фигуры на тёмной странице переключаются с `multiply` на
`screen`, иначе умножение на тёмном фоне дало бы невидимую подложку.

Смена темы перерисовывает видимые страницы (`renderEpoch`) без повторного чтения
файла; позиция и масштаб сохраняются.

### 9. Растр рисуется откреплённым и вставляется готовым

pdf.js последовательно заливает канвас фоном (белым) и содержимым. Если канвас
уже в DOM, на экране мелькала бы белая страница до перекраски — особенно заметно
при смене масштаба. Поэтому растр рисуется в **откреплённый** канвас и
вставляется на место одним кадром после перекраски, для обеих веток — первой
отрисовки и перерисовки окна. До готовности виден фон рамки страницы
(`--page-background`, в тёмной теме — бумага), а не белый лист.

### 10. Выделение текста рисует собственный слой

Браузерный `::selection` кладёт прямоугольник на каждую строку; у текстового слоя
pdf.js высота строки включает межстрочный интервал, поэтому при плотном
интерлиньяже полосы соседних строк перекрываются — на стыках заливка темнеет, а
полупрозрачный цвет поверх растра мутит текст. Поэтому плагин рисует собственный
слой `.selection-layer`: полосы сливаются и обрезаются тем же приёмом, что и
подсветки заметок (`lineRects`), а заливка ложится на страницу режимом наложения
(умножение на светлой стороне, осветление на тёмной) — так же, как подсветка
цитаты, поэтому растр остаётся чётким. Нативное `::selection` делается
прозрачным и служит только копированию. Цвет — единый токен `selection` темы
области чтения, в тон палитре (Gruvbox — приглушённый стально-синий, Mist —
привычный синий); в EPUB выделение по-прежнему браузерное по этому токену.

*Почему не поднять непрозрачность браузерного выделения:* перекрытие полос и
мутность растра остаются — их не лечит цвет. Слой перерисовывается на
`selectionchange`, после отрисовки страницы и снимается при её освобождении.

## Risks / Trade-offs

- **[Расхождение тонов заметки в списке при разных темах интерфейса и чтения]**
  список — область интерфейса, а метка берёт тон темы чтения → возможен
  слабый контраст на чужой стороне → подбирать тона заметок читаемыми на обеих
  сторонах и покрыть проверкой контраста; при необходимости вернуться к
  раздельным наборам (метка — интерфейс, страница — чтение).
- **[PDF на тёмном фоне: перекраска растра]** страница PDF перекрашивается в
  цвета темы (бумага → фон темы, текст → цвет текста темы); цена — обход
  пикселей видимых страниц и то, что цветные иллюстрации и сканы темнеют,
  перекрашиваясь в тон палитры (остаются узнаваемыми, но не «как в оригинале»).
  Альтернативы: инверсия канваса CSS-фильтром ломала бы оттенок целиком;
  нейтральный почти-чёрный фон слишком контрастен и безлик.
- **[Дублирование резолва значений в двух песочницах]** возможен дрейф, если
  значения задать и в CSS, и в TS → единственный источник — модуль
  `reader-theme.ts`; CSS-токены области чтения на уровне оболочки не вводим.
- **[Визуальные эталоны]** смена оформления области чтения меняет снимки →
  эталоны пересоздать осознанно, вместе с проверкой, что обычный (светлый)
  режим не деградировал.
- **[Изоляция EPUB]** документ собирается один раз; смена темы через атрибут
  обязана не сбрасывать прокрутку → покрыть тестом, что позиция и подсветки
  сохраняются при переключении темы.

## Migration Plan

Изменение добавочное: новое поле `reader.theme` со значением по умолчанию
`light` сохраняет текущий вид книги, миграция данных не нужна. Откат — удаление
поля и возврат к фиксированному светлому оформлению документов; сохранённое
необязательное значение безвредно.
