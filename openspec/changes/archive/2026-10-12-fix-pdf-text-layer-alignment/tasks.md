  обращения: метрики `spanLeft`/`spanRight` совпадают до сотых. Проверка:

  метрики не меняются. Проверка: `getTextContent` с

- [x] 1.3 Замерить расхождение невидимого слоя с растром: правый край строки
  короче чернил на ~0.7–1 % (медиана по странице 9.2 px). Проверка: замер по
  профилю чернил на странице 8 `Скиннер Б.Ф.…`.
- [x] 1.4 Установить, почему расширение выглядит правильно: нативное `::selection`
  в Chromium (852) выходит за рамку span (845) до чернил (852), а в WebKitGTK —
  нет (844). Проверка: пиксельный замер нативного выделения и кастомной заливки в
  обоих движках.

## 2. Выравнивание невидимого слоя скана по растру

- [x] 2.1 `isInvisibleScan(page)`: признак «есть изображение, есть текст и весь
  текст невидим (`rendering mode 3`)» через `getOperatorList`; кэш по номеру
  страницы. Проверка: на цифровом PDF признак ложный, на скане — истинный.
- [x] 2.2 `alignTextLayer`: строки группируются по вертикальному перекрытию,
  у каждой берётся последний span, его `scaleX` растягивается до правого края
  пятна чернил (пробелы короче 0.7 кегля перешагиваются, длинные разрывы нет).
  Проверка: медиана недобора правого края по странице 9.2 px → 0.
- [x] 2.3 Отсев ложных срабатываний: горизонтальные линейки, растяжение >1.3×,
  обрыв пятна у края канваса, запрет чтения пикселей. Проверка: шапка, линейка и
  подстрочные примечания не растягиваются.
- [x] 2.4 Выравнивание применяется только `overlay`-независимо, после вставки
  слоя в документ; координаты — в долях страницы (как у маски и якоря заметки).
  Проверка: якоря заметок и подсветка цитаты работают.

## 4. Вертикальные метрики слоя цифровой страницы

- [x] 4.1 Установить причину расхождения высоты полос: прямоугольники
  `Range.getClientRects()` (полосы выделения, цитаты) берут высоту из инлайн-бокса
  шрифта слоя, а не из межстрочного шага. У встроенного шрифта цифровой страницы
  бокс ниже шага (замер: 24 px при шаге 28.8 → щели), у запасного `monospace` на
  сканах выше шага (замер: 42 px при шаге 28.6 → полосы залезают на соседние
  строки). Официальный просмотрщик pdf.js даёт те же числа, но маскирует их
  нативным `::selection`.
- [x] 4.2 `tileByLine` в вьюере приводит полосы к межстрочному шагу: куски одной
  строки сливаются по перекрытию, а границы соседних полос одного абзаца проходят
  посередине между серединами строк (внешние края обрезаются на полшага, за рамку
  строки не выходя). Промежуток между абзацами (разрыв больше высоты бокса) не
  заливается. Используется и полосами-метками, и подсветкой цитаты, и маской
  заливки; прежняя функция `selectionBands` удалена. Проверка: оба файла
  (Смит, Скиннер) в WebKit и Chromium — зазор между полосами ~0, высота полосы
  равна шагу.
- [x] 4.3 Отказ от `applyFallbackMetrics`: возврат вертикальных метрик запасного
  семейства через `ascentOverride`/`descentOverride` в WebKitGTK не применяется
  (замер: высота строки остаётся 24 px вместо 34.8 px), поэтому вертикаль надёжнее
  чинить приведением полос к шагу. Встроенный шрифт страницы для букв сохранён.
- [x] 4.4 e2e-проверка: у страницы с плотным межстрочным шагом полосы соседних
  строк стыкуются без щелей и нахлёста; у скана первой/последней строки полоса
  обрезается на полшага и не «торчит». Проверка: red→green подтверждён; тесты
  «полоса выделения стыкуется по межстрочному шагу» и «полосы выделения стыкуются
  по межстрочному шагу».
- [x] 4.5 Убедиться, что прежний фикс правого края скана не сломан: тесты скана и
  выделения проходят. Проверка: `tests/e2e/pdf-reader.spec.ts` — 40 passed.
