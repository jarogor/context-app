## Context

См. proposal.md — Why. Замеры: первая компиляция source-WASM ~3.4 c, из кэша
~80 мс; базовые плагины ~2.4 c. Обход библиотеки и кэшированная загрузка ни при
чём. Extism 1.30 строит `wasmtime::Engine` и настраивает кэш через
`PluginBuilder::with_cache_config`; по умолчанию используется системный путь
(`wasmtime::Cache::from_file(None)`, фактически `~/.cache/wasmtime`). Публичный
`WasmInput`/`Wasm::File`/`Wasm::Data` принимает только сырой WASM.

## Goals / Non-Goals

**Goals:**

- Убрать заметную паузу до прогресс-бара при первом открытии библиотеки.
- Сделать кэш компиляции предсказуемым (в данных приложения).
- Зафиксировать решение по предкомпиляции `.cwasm`.

**Non-Goals:**

- Замена extism или wasmtime.
- Изменение контракта плагинов и их логики.

## Decisions

### D1. Предкомпиляция `.cwasm` — недоступна через extism 1.30

Проверено по исходникам `extism 1.30.0` (wasmtime 43): публичный API
(`WasmInput`, `Wasm::File`/`Wasm::Data`) принимает только сырой WASM;
загрузки предкомпилированного модуля нет. Значит «пункт 3» в исходном виде
требует либо апстрим-поддержки, либо форка. Решение: зафиксировать ограничение и
реализовать достижимый аналог — постоянный кэш компиляции + прогрев. Если
появится API, вернуться к `.cwasm`.

### D2. Явный постоянный кэш в данных приложения

`PluginBuilder::with_cache_config` принимает путь к конфигурационному файлу
wasmtime (не каталог): файл с секцией `[cache]` и абсолютным `directory`.
Ядро готовит `<app_data>/app-state/wasm-cache/config.toml`, чтобы кэш
гарантированно существовал и не зависел от системного окружения. При
недоступности — не отказывать в загрузке, а компилировать обычным образом.

### D3. Предварительный прогрев source-плагинов

При старте приложения скомпилировать bundled source-плагины (без активной
библиотеки) в фоне, чтобы первичная компиляция не попадала на первое открытие.
Альтернатива — прогрев в фоне при первом показе списка библиотек.

## Risks / Trade-offs

- [Прогрев нагружает старт] → Выполнять в фоне/лениво, не блокируя UI.
- [Кэш инвалидируется при пересборке `.wasm`] → Неизбежно; в проде модули
  стабильны, кэш живёт между запусками.
- [Версия wasmtime в кэше несовместима] → Кэш версионируется wasmtime; при
  несовместимости — обычная компиляция.

## Open Questions
