## Context

См. `proposal.md` — Why. Состояние, важное для подхода:

- Стор умеет только `install`/`uninstall`; базовый плагин `plugin-store` вызывает
  привилегированные host-функции `store_install`/`store_uninstall`/`store_installed`,
  которые выдаются только объявившим их плагинам.
- `PluginRuntime::load_kinds` грузит плагины из директорий без понятия
  активности; `PluginSession::install` загружает runtime для корня.
- История (`library_history`, ядро) фильтрует записи по доступным source-плагинам,
  обнаруживаемым по манифестам (`plugin::discover_source_plugins`).
- App-level состояние приложения хранится в `app_state_root`
  (`resolve_app_state_root`), базовые плагины отключать нельзя.

## Goals / Non-Goals

**Goals:**

- Реестр отключённых плагинов у ядра; загрузка пропускает отключённые.
- Привилегированные host-функции стора: перечень отключаемых плагинов и
  переключение активности.
- Базовые плагины каркаса не отключаются.
- История учитывает активность провайдера.
- Переключатель активности в UI стора.

**Non-Goals:**

- Горячая перезагрузка без переоткрытия библиотеки/перезапуска.
- Права/подпись/доверие плагинов.
- Отключение frontend-only `ui`-плагинов сверх общего механизма.

## Decisions

### 1. Реестр активности у ядра

Новый модуль `plugin/activation.rs` хранит множество отключённых имён в
`<app_state_root>/disabled-plugins.json` (`{ "disabled": ["name", ...] }`).
Ядро читает реестр при старте и при каждой (пере)конфигурации сессии.
`PluginSession` получает `set_disabled_plugins(Vec<String>)`; `install` передаёт
набор в `PluginRuntime`, который пропускает отключённые плагины (кроме базовых).
Обоснование: активность должна влиять на загрузку до создания runtime, а знание
о ней — общее для сессии и стора.

### 2. Перечень отключаемых плагинов

Новая host-функция `store_plugins` возвращает JSON-список отключаемых плагинов из
поставляемых, dev- и пользовательской директорий: `{ name, kind, description,
enabled, removable }`. `kind` — `source`/`extension`; базовые исключены;
`removable` — плагин найден в пользовательском каталоге. Поставляемый Calibre
попадает в перечень с `removable: false` и может быть отключён.

### 3. Переключение активности

Новая host-функция `store_set_enabled(name, enabled)`:
- отклоняет базовые плагины и неизвестные имена;
- обновляет реестр активности;
- ядро обновляет `PluginSession`-набор, чтобы изменение применилось при
  следующей загрузке.

Обе host-функции выдаются только плагинам, объявившим их в `host_functions`
(как существующие `store_*`).

### 4. История учитывает активность

`library_history_list` формирует набор доступных провайдеров как
«обнаруженные source-плагины минус отключённые». Скрипты `library-history`
спеков расширяются сценарием «провайдер отключён».

### 5. UI стора

`plugin-store-ui` показывает список плагинов с переключателем активности
(включён/отключён) и, для `removable`, действие удаления. После переключения
показывается подсказка о необходимости переоткрыть библиотеку/перезапустить
приложение (горячей перезагрузки нет).

## Risks / Trade-offs

- [Отключение активного провайдера не перезагружает текущую сессию] → UI сообщает о переоткрытии; изменение применяется при следующем `install`.
- [Пользователь отключит нужный плагин] → переключатель легко вернуть; базовые защищены.
- [Перечень сканирует директории по манифестам] → дёшево, без загрузки WASM.
- [Базовые определяются по `kind` манифеста] → надёжно, совпадает с загрузкой.

## Migration Plan

1. Ввести реестр активности и фильтрацию загрузки.
2. Добавить host-функции `store_plugins`/`store_set_enabled` и гейтинг.
3. Обновить базовый плагин `plugin-store` (операции) и `plugin-store-ui` (переключатели).
4. Учесть активность в истории.
5. Откат: изменения ядра и frontend; вернуть из git.
