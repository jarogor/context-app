## Context

См. `proposal.md` — Why. Текущее состояние, важное для решения:

- Чтение EPUB устроено так: приложение просит source-плагин `library` операцией
  `content`, плагин разбирает файл и возвращает главы (заголовок + HTML), а
  `src/lib/ReaderPage.svelte` собирает их в один HTML и показывает в песочнице.
  Разбор формата — в плагине, показ — в приложении.
- Отдельный интерфейс чтения уже есть (`src/lib/reader/`): формат определяется по
  каталогу, поддерживаемым считается только `epub`. Это шов, рассчитанный на
  замену загрузчика, но модель содержимого (`chapters[] → html`) подходит только
  текстовым форматам.
- Пакет плагина — zip с манифестом и WASM-модулем (`plugin-store`); типы плагинов
  — `base`, `source`, `extension`. WASM без WASI не имеет доступа к файловой
  системе и сети, кроме host-функций.
- Решение «никакого фронтенда в плагинах» зафиксировано: единство и контроль
  оформления важнее свободы плагинов. Автономные фронтенд-плагины
  (`plugins/*`, iframe, `kind: "ui"`) подлежат удалению.
- `declarative-plugin-ui` (плагин описывает интерфейс, приложение рисует)
  отложен и в это изменение не входит.

## Goals / Non-Goals

**Goals:**

- Дать формат-рисующим книгам (PDF и подобным) читаться плагином, не добавляя в
  ядро знаний о форматах.
- Сохранить единство оформления: всё управление страницы чтения — приложение и
  дизайн-система, плагин рисует только содержимое.
- Дать плагину ровно то, что невыразимо декларативно — рисование страниц — и
  изолировать это рисование.
- Оставить EPUB работающим без изменений для пользователя.

**Non-Goals:**

- Сам плагин PDF и выбор движка рендера — отдельный последующий шаг.
- Декларативный UI и SDK (`declarative-plugin-ui`) — не затрагиваются.
- Заметки, аннотации и якоря в тексте — будущие шаги; протокол обмена должен
  оставить для них место, но не реализовывать.
- Произвольная вёрстка от плагинов: свобода ограничена областью содержимого.

## Decisions

### D1. Отдельный тип плагина с модулем рисования

Вводится тип плагина рабочего места. Он объявляет поддерживаемые форматы и несёт
модуль рисования (статические файлы) помимо манифеста; WASM-часть может
отсутствовать или отвечать за данные. Модуль рисования исполняется в изоляции.

Альтернативы: собирать движок PDF в WASM и рисовать внутри плагина (тяжёлая
сборка, медленный рендер, дублирование того, что уже есть в JS); встроить читалку
PDF в приложение (не даёт «плагина рабочего места» и снова привязывает ядро к
формату). Выбранный путь даёт настоящий плагин при разумной цене.

### D2. Плагин рисует только область содержимого

Приложение владеет каркасом страницы чтения: шапка, нижняя панель, масштаб,
навигация, поиск, будущая панель заметок. Плагин получает прямоугольник области
содержимого и рисует в нём. Управление строится приложением по возможностям,
которые сообщил плагин.

Альтернатива: отдать плагину всю страницу (как автономный фронтенд-плагин) —
отклонена: разрушает единство интерфейса, ради которого принимался отказ от
фронтенда. Компромисс «область содержимого» — минимально необходимое исключение.

### D3. Обмен — минимальный протокол, opaque для ядра

Приложение → плагину: открыть книгу, задать масштаб, перейти к позиции (позже —
поиск/выделение). Плагин → приложению: готовность или ошибка, возможности,
текущая позиция, запросы (открыть ссылку, открыть во внешнем). Ядро доставляет
сообщения как opaque-данные и не интерпретирует их.

Альтернатива: колбеки или прямой доступ плагина к приложению — отклонена: даёт
реентерантность и нарушает изоляцию. Унидирекциональный обмен согласуется с
подходом, заложенным для будущего декларативного UI.

### D4. Выбор плагина по формату; ядро не знает форматов

Формат книги берётся из каталога. Приложение выбирает установленный и включённый
плагин рабочего места, объявивший этот формат. Ядро лишь маршрутизирует книгу и
сообщения. Правила о конкретных форматах в ядре отсутствуют.

Альтернатива: таблица «формат → встроенная реализация» в ядре — противоречит
plugin-first. Отклонена.

### D5. Данные книги — непрозрачная ссылка, а не разобранный контент

Плагину рабочего места передаётся непрозрачная ссылка на файл книги, по которой
он получает содержимое (потоком или частями). Приложение и ядро не разбирают
файл. Для EPUB сохраняется существующий путь через `content` source-плагина.

Альтернативы: возвращать весь файл через WASM в base64 (тяжело для больших PDF,
упирается в память Extism); отдавать плагину путь и позволять читать файл
напрямую (нарушает изоляцию и «ядро не резолвит пути»). Непрозрачная ссылка
держит границу.

### D6. Изоляция модуля рисования

Модуль рисования исполняется в песочнице без доступа к файловой системе, сети и
приложению, кроме объявленного обмена. Недоверенный код плагина и недоверенное
содержимое книги изолированы от приложения.

Альтернатива: исполнять код плагина в общем окне приложения — риск безопасности и
нарушение изоляции. Отклонена.

### D7. Исключение узкое и постоянное

«Плагин рисует только содержимое» — постоянное исключение из отказа от фронтенда,
а не временная уступка. Отказ от автономных фронтенд-плагинов, рисующих целые
экраны, сохраняется и выполняется отдельной задачей.

### D8. Пакет расширяется модулем рисования

Пакет плагина рабочего места: манифест (форматы, модуль) + WASM (при наличии) +
файлы модуля рисования. Установка проверяет версию контракта и безопасность
путей; удаление удаляет модуль. Переиспользуется существующая работа `plugin-store`.

## Risks / Trade-offs

- [Единство дизайна под угрозой из-за кода плагина] → Рисование строго ограничено
  областью содержимого; всё управление приложения. Возврат к свободному интерфейсу
  плагина не допускается.
- [Безопасность исполняемого кода сторонних плагинов] → Песочница и минимальный
  мост сообщений; никакого прямого доступа к системе.
- [Большие PDF и память] → Непрозрачная ссылка и потоковая/частями передача;
  избегать base64 целого файла через WASM.
- [Два пути контента (source `content` и плагин рабочего места)] → Единый интерфейс
  страницы чтения; шапка и панель не зависят от источника содержимого.
- [Пересечение с отложенным `declarative-plugin-ui`] → Плагины рабочего места не
  используют `ui-schema`; изменения независимы.
- [Сторонний рендер даёт разное качество] → Первый плагин делаем сами; качество
  контролируем на первом формате.

## Migration Plan

Миграции данных нет. Порядок: ввести тип плагина и модуль рисования в контракт и
пакет → предоставить область содержимого и обмен в приложении → выбор плагина по
формату и доступность чтения по установленным плагинам → пример плагина рабочего
места. EPUB продолжает работать прежним путём. Откат — возврат ветки; внешних
плагинов рабочего места ещё нет, данные не мигрируются.

## Open Questions

- Протокол обновления области: полная перерисовка по команде vs инкрементальные
  сообщения — решается при реализации первого плагина.
- Нужна ли плагину рабочего места WASM-часть (данные, метаданные, оглавление) или
  на первом шаге достаточно модуля рисования — решается на примере PDF.
- Точная форма непрозрачной ссылки и способ потоковой передачи больших файлов —
  решается при реализации, на спеки не влияет.
