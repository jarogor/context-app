## Context

Сейчас `Library::open` создаёт in-memory SQLite-каталог и каждый раз полностью вызывает сканер Calibre. Каталог уже используется командами списка, поиска, обложек и открытия файла, поэтому изменение должно сохранить существующий read-only контракт и единый интерфейс чтения. Служебный индекс нельзя размещать в выбранной директории: она может принадлежать Calibre и одновременно изменяться другим процессом. Пользовательский UX не должен содержать настроек индекса: служебное хранилище размещается в `.booklib` внутри директории приложения.

## Goals / Non-Goals

**Goals:**

- Разделить сохраняемый снимок индекса и рабочее in-memory представление каталога.
- Быстро восстанавливать рабочий каталог из индекса при повторном открытии.
- Обрабатывать обычные события файловой системы на уровне директории книги и применять их атомарно.
- Поддержать полную перестройку как fallback для повреждённого индекса, потери событий и неоднозначных изменений.
- Управлять жизненным циклом фоновой синхронизации при открытии, смене и завершении приложения.
- Обеспечить атомарную запись индекса и отсутствие записи в Calibre.
- Вернуть отдельную страницу книги и использовать возврат к списку как проверяемый сценарий повторного чтения готового индекса.

**Non-Goals:**

- Изменение формата, базы данных или настроек самой Calibre.
- Синхронизация изменений метаданных обратно в Calibre.
- Поддержка распределённого или общего индексного хранилища между несколькими процессами.
- Гарантия мгновенного отражения изменений во frontend без механизма обновления UI; способ доставки события можно выбрать при реализации при сохранении требований спеки.

## Decisions

### Отдельный локальный индекс на библиотеку

Индекс следует хранить в скрытой директории `.booklib` рядом с исполняемой программой, с именем или вложенной директорией, производной от хеша канонического пути Calibre. Пользователь не выбирает это расположение и не управляет индексом. Запись должна содержать версию схемы, канонический корень, записи книг, относительные пути файлов и fingerprint наблюдаемых файлов/директорий. Версия схемы позволяет отвергать старый формат без попытки миграции.

Рассматривалась запись индекса в Calibre `metadata.db` или отдельный файл внутри библиотеки. Оба варианта нарушают границу read-only, конфликтуют с Calibre и могут появиться в синхронизируемой пользователем директории, поэтому отклонены.

### Рабочий каталог восстанавливается из снимка

При открытии Calibre сначала читается и проверяется локальный индекс, затем из него транзакционно строится in-memory SQLite-каталог. Если индекс не прошёл проверку, используется текущий полный scanner, а новый снимок записывается атомарно через временный файл и rename в локальном хранилище.

Рассматривалось каждый раз проверять все исходные файлы перед использованием индекса. Это сохраняет корректность, но возвращает почти всю стоимость полного сканирования, поэтому проверка ограничивается сохранёнными fingerprint и событиями watcher; при сомнении выполняется полная перестройка.

### Watcher с очередью событий и coalescing

После успешного открытия запускается один watcher на корневой путь Calibre и канал событий во внутренний worker. Worker группирует события короткими пакетами, определяет затронутые директории книг по относительному пути и перечитывает только эти директории. Для добавления, изменения и удаления запись книги заменяется в рабочем каталоге одной транзакцией, затем снимок индекса обновляется атомарно.

Если событие нельзя связать с конкретной книгой, watcher сообщает об overflow/error или структура директории перестала соответствовать ожидаемой, worker выполняет полный scanner. Это проще и надёжнее эвристической попытки восстановить неполный каталог.

### Единый владелец состояния и остановка при смене библиотеки

Состояние Calibre-каталога должно включать рабочее соединение, индексный снимок и handle фоновой задачи. Команда `open_library` сначала строит новое состояние, затем заменяет старое после успешного запуска; старый worker получает сигнал остановки и join/дожидается завершения. Это исключает запись событий старой библиотеки в новый каталог.

Рассматривалась глобальная независимая задача без владельца в `Library`. Такой вариант усложняет смену библиотеки и создаёт гонки с `Mutex<Library>`, поэтому отклонён.

### Обновление UI через событие изменения каталога

После применения batch worker должен уведомлять frontend событием уровня «каталог изменился». UI повторно вызывает уже существующие `list_books`/`search_books` и обновляет обложки. Клик по карточке должен переходить на отдельную страницу книги, а не вызывать системное открытие; страница содержит ссылку системного открытия и возврат в список. Пока batch не применён, команды чтения видят старый согласованный snapshot; возврат в список не инициирует полный scanner.

## Risks / Trade-offs

- [Риск] Частые изменения Calibre могут порождать много событий и повторных чтений → coalescing событий и debounce перед одной синхронизацией.
- [Риск] Файл может быть замечен до окончания записи Calibre → повторная попытка чтения книги после короткой задержки; при неуспехе сохранение старого snapshot и последующая повторная синхронизация.
- [Риск] Индекс может занимать заметный объём для очень большой библиотеки → хранить только данные, необходимые для восстановления существующего каталога, и относительные пути.
- [Риск] Атомарный rename локального индекса может быть недоступен на отдельной файловой системе → ошибка записи не должна ломать чтение; рабочий каталог остаётся доступным, следующий запуск перестроит индекс.
- [Риск] Watcher не гарантирует доставку каждого события → считать overflow/error основанием для полной перестройки, а не пытаться продолжить частичную синхронизацию.

## Migration Plan

1. При первом открытии текущего формата выполнить полное сканирование и создать индекс в новом локальном хранилище.
2. При последующих открытиях использовать индекс после проверки версии, корневого пути и fingerprint.
3. При ошибке чтения или проверки удалить/заменить только локальный индекс и построить его заново; директорию Calibre не откатывать и не изменять.
4. При откате версии приложения старый индекс считать несовместимым и безопасно перестроить его.
