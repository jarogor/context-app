## Context

См. proposal.md — Why. Тестовый стек: `@texture/ui` проверяется Vitest +
`@testing-library/svelte`; области — Playwright с мок-мостом
(`VITE_MOCK_BRIDGE=1`), который подменяет `invoke`/`dialog`/`listen`
(`packages/testing`). Сейчас есть один компонентный тест и четыре браузерных,
проверяющих лишь видимость текстов.

## Goals / Non-Goals

**Goals:**

- Осмысленное покрытие текущих областей, ломающееся при регрессиях.
- Детерминированность (локаль/таймзона) и переиспользуемые фикстуры.
- Простота добавления новых сценариев.

**Non-Goals:**

- Полный охват всех веток; юнит-тесты wasm-плагинов (уже есть).
- Визуальная регрессия по всем страницам (только снимок оболочки).

## Decisions

### D1. Два уровня, как в pdf.js

Компонентные тесты дизайн-системы (быстрые, без браузера) и браузерные
e2e-сценарии (реальный браузер + мок-мост). Это повторяет практику pdf.js
(unit + integration) и уже принято в проекте.

### D2. Переопределяемые фикстуры мока

`app-bridge` при инициализации мока использует `window.__TEXTURE_MOCK_CONFIG__`,
если он задан, иначе `defaultMockConfig()`. Тест через `page.addInitScript`
задаёт нужные ответы (книги, уведомления, плагины стора), не меняя общий файл
фикстур. Базовые фикстуры при этом остаются осмысленными по умолчанию.

### D3. Детерминированное окружение

В `playwright.config.ts` фиксируются `locale: 'ru-RU'` и
`timezoneId: 'Europe/Moscow'` — как приём избавления от зависимости от локали
(у нас уже был баг с 12-часовым форматом).

### D4. Сценарии по областям

- Оболочка: верхняя панель, активное (нажатое) состояние кнопок, переключение
  разделов, панель уведомлений.
- «Библиотеки»: список истории, время, признак активной библиотеки, автовозврат
  после успешного открытия.
- Библиотека: список книг, поиск, пустое состояние, обложка-заглушка.
- Настройки: рендер секций, автосохранение дискретного поля.
- Стор: перечень плагинов, переключение активности.
- Уведомления: записи со степенью, скрытие технических по умолчанию, включение
  технических.

## Risks / Trade-offs

- [Хрупкость e2e из-за селекторов] → опираться на доступные роли и метки
  (`getByRole`, `aria-*`), а не на текст/классы.
- [Зависимость iframe-тестов от сборки плагинов] → `npm run dev` собирает
  frontend-плагины; тесты запускаются после сборки.
