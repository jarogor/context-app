## Context

Сейчас открытие библиотек реализовано прямо в ядре: сканер директорий, построение виртуального каталога, индекс и его актуализация живут «рядом» с плагинной подсистемой, а плагины почти не участвуют в работе с библиотеками. Плагины загружаются только из `plugins/` библиотеки, а host-функции (`log`) не знают о корне библиотеки — песочницы для ФС нет. Мотивацию см. в `proposal.md`.

## Goals / Non-Goals

**Goals:**

- Ввести тип плагина `source` и контракт v2 с host-функциями ФС `fs_list_dir`/`fs_read_text`.
- Перенести модели, индекс-кэш и виртуальный каталог в общий модуль `sources/`; сканер директорий переезжает в базовый плагин.
- Сделать `Library` generic-внешним источником (`Portable | External`) с именем источника.
- Реализовать базовый плагин создания/открытия библиотеки (`library-plugin`): общий сканер любой директории с книгами (без привязки к конкретному формату каталога), манифест `kind: "source"`, поставляется в `resources/plugins/library/`.
- Загружать плагины из `plugins/` библиотеки и из поставляемых ресурсов, чтобы внешняя библиотека открывалась без собственной `plugins/`.

**Non-Goals:**

- Чтение бинарных метаданных: сканирование ФС выполняется плагином через host-функции, метаданные извлекаются из структуры каталога и имён файлов.
- Запись в директорию внешней библиотеки.
- Несколько источников в одной библиотеке одновременно.
- Пользовательское управление плагинами в UI.

## Decisions

### Runtime переносится в `Library`

`PluginRuntime` становится полем `Library` и больше не держится отдельным managed-состоянием. `open_library` и `open_for_selection` пересоздают библиотеку вместе с runtime (с активным корнем), а `sync_if_needed` напрямую вызывает `scan_book` координатора через `&mut runtime`. Это устраняет гонки двух состояний и даёт `Library` доступ к опросу плагинов. Альтернатива — оставить отдельное состояние и вставлять runtime в вызовы координатора — усложняет команды и `sync_if_needed`, поэтому отклонена.

### Контракт v2 и host-функции ФС

`CONTRACT_VERSION = 2`, в манифест добавляется `kind: "extension" | "source"` (default `extension`). `HOST_FUNCTIONS` расширяется: `log`, `fs_list_dir`, `fs_read_text`. Host-состояние runtime хранит активный корень библиотеки; обе ФС-функции получают относительный путь из плагина и резолвят его через канонизацию с проверкой вхождения в корень (`candidate.starts_with(&root)`). Запись и сеть остаются запрещены (`disallow_all_hosts`, без WASI). Хост `fs_list_dir` возвращает JSON-массив имён записей, `fs_read_text` — содержимое файла. Ошибки вне песочницы возвращаются плагину как ошибка вызова без раскрытия пути.

### Протокол source-плагина через `invoke`

Экспортируемая функция `invoke` для source-плагинов разбирает JSON-запросы:

- `{"action":"probe"}` → `{"supported": true|false}` — распознавание корня (наличие книг в структуре «автор/книга» без требования конкретного формата метаданных).
- `{"action":"scan"}` → `{"books":[ExternalBook, ...]}` — полное сканирование.
- `{"action":"scan_book","path":"Автор/Книга"}` → `{"book": ExternalBook|null}` — частичное пересканирование папки.

`ExternalBook` (и `ExternalFile` с `ExternalFileKind::Book|Cover`) описывают книгу теми же полями, что использует ядро: title, authors, tags, series, files (относительные пути + формат). Это позволяет `catalog.rs` и `index.rs` переиспользовать существующие построители дословно.

### `sources/` — общий источник в ядре

Модуль `sources/` содержит модели (`ExternalBook` и аналоги), индекс-кэш (`.booklib`, хеш корня) и построители виртуального каталога. Добавляется координатор: `probe(runtime, root) → Option<String>` (имя плагина-источника, поддержавшего корень), `scan(runtime, root, source)`, `scan_book(runtime, root, source, path)`. Этапы `open`/`prepare_selected` используют координатор вместо прямого вызова сканера ядра.

### `Library` — generic внешний источник

`LibraryMode::Portable | External`; `as_str` возвращает `"portable" | "external"`. У `Library` появляется поле `source_name: Option<String>`. `promote_external(connection, index, source_name)`, `build_external_index`. Ветки команд и `import_book`/`get_book_content` переписываются на `External`. Проба «это внешняя библиотека» делается опросом плагинов, а не внутренним распознаванием структуры ядра.

### Загрузка плагинов из двух мест и seeding

`PluginRuntime::load` принимает список директорий плагинов: `plugins/` библиотеки и `resources/plugins/` приложения. Для портируемых библиотек поставляемые плагины (demo, базовый источник) копируются в `plugins/` при первом старте (как сегодня — `seed_demo_plugin` обобщается в `seed_plugins`). Для внешних библиотек запись в корень запрещена, поэтому поставляемые плагины читаются напрямую из ресурсов приложения.

### Базовый плагин создания/открытия библиотеки

`src-tauri/library-plugin/` — отдельный WASM-crate (extism-pdk, serde). Общий сканер директории с книгами: читает структуру каталога через `#[host_fn] fs_list_dir`/`fs_read_text` (относительные пути, без std::fs). Книги ищутся по расширениям файлов в папках вида «автор/книга»; метаданные (название, авторы) берутся из имён папок и не требуют файла метаданных. `probe` определяет пригодность корня по наличию книг. Сборка — `scripts/build-library-plugin.sh` → `src-tauri/resources/plugins/library/` (wasm + manifest `kind: "source"`, contract v2). Тесты сканера переезжают в crate плагина.

### UI и команды

`get_library_info` возвращает `{ kind: "external", source_name, indexing, stage }`. Фронтенд: `types.ts` (`kind: 'portable' | 'external'`, `source_name`), импорт EPUB скрыт для `external`. Принято рекомендованное значение строки `"external"` (с именем источника); значение вида конкретного формата отклонено как привязка к конкретному источнику.

## Risks / Trade-offs

- [Риск] Контракт v2 ломает существующий demo-плагин → демо пересобирается и обновляет манифест на этапе контракта; старые плагины с версией 1 корректно отклоняются.
- [Риск] Плагин-источник доверяется на чтение ФС → жёсткая песочница: только чтение, только внутри корня, без сети; host-функции не раскрывают пути вне песочницы.
- [Риск] Partial re-scan требует поддержки `scan_book` в плагине → базовый плагин реализует `scan_book` с самого начала.
- [Риск] Внешняя библиотека не имеет собственной `plugins/` → поставляемые плагины читаются из ресурсов приложения отдельным источником загрузки.
- [Риск] Повторный `probe` на каждый `open` добавляет вызовы плагина → probe дёшев (корневой обход ограничен), а индексированный каталог не требует полного сканирования.

## Migration Plan

1. Контракт v2 в `plugin/` + пересборка demo-плагина + тесты.
2. `sources/`: модели, индекс, каталог, координатор source-плагинов.
3. `Library` переводится на координатор источников; сканирование переезжает в плагин.
4. Базовый плагин в `src-tauri/library-plugin/` с тестами.
5. Команды/UI на `external`.
6. Документация и OpenSpec-артефакты (архивация этого change).

Каждый этап — отдельный шаг с проверками (`cargo test`, `clippy`, `fmt`, `npm run check/build`); этапы выполняются по порядку, откат — на завершённый этап до следующего.
