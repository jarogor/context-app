## MODIFIED Requirements

### Requirement: Контракт extension point(ов)

Подсистема SHALL определять контракт extension point(ов) — явно объявленный набор host-функций и ожидаемых экспортируемых функций плагина, с которыми плагины могут взаимодействовать. Контракт SHALL быть стабильной точкой расширения приложения и документироваться. Контракт SHALL иметь версию; приложение SHALL отклонять плагины с неподдерживаемой версией контракта. Манифест плагина SHALL содержать поле `kind` со значением `extension` или `source`; плагины, не объявившие `kind`, SHALL считаться плагинами расширения (`extension`).

#### Scenario: Плагин, соответствующий контракту

- **WHEN** плагин экспортирует функции, ожидаемые контрактом, и использует только объявленные host-функции
- **THEN** плагин успешно загружается и может быть вызван в точке расширения приложения

#### Scenario: Плагин с несоответствующим контракту

- **WHEN** плагин не предоставляет ожидаемых контрактом экспортируемых функций
- **THEN** приложение отклоняет загрузку плагина с сообщением об ошибке, не нарушая работу остальных плагинов

#### Scenario: Плагин с неподдерживаемой версией контракта

- **WHEN** манифест плагина объявляет версию контракта, отличную от поддерживаемой приложением
- **THEN** приложение отклоняет загрузку плагина с сообщением об ошибке, не нарушая работу остальных плагинов

#### Scenario: Плагин без объявленного kind

- **WHEN** манифест плагина не содержит поле `kind`
- **THEN** приложение загружает плагин как плагин расширения (`extension`)

#### Scenario: Ошибочный kind плагина

- **WHEN** манифест плагина содержит значение `kind`, отличное от `extension` и `source`
- **THEN** приложение отклоняет загрузку плагина с сообщением об ошибке, не нарушая работу остальных плагинов

### Requirement: Загрузка плагинов из локальной папки

Подсистема SHALL загружать плагины из папки `plugins/` портируемой директории и из поставляемых приложением плагинов, обнаруживать плагины по их манифесту и загружать их с помощью Extism host runtime. Поставляемые плагины SHALL добавляться в библиотеку при первом старте. Загрузка плагинов SHALL происходить при запуске приложения и при открытии библиотеки, чтобы внешняя библиотека могла использовать плагины, даже если в её корне нет собственной папки `plugins/`.

#### Scenario: Загрузка demo-плагина из папки plugins

- **WHEN** в папке `plugins/` присутствует корректный demo-плагин с манифестом и файлом `.wasm`
- **THEN** приложение загружает плагин в Extism runtime и может вызвать его в точке расширения

#### Scenario: Отсутствие плагинов в папке

- **WHEN** папка `plugins/` пуста или не содержит корректных плагинов
- **THEN** приложение запускается без ошибок, плагинная подсистема остаётся активной, но загруженных плагинов нет

#### Scenario: Плагин-источник для внешней библиотеки

- **WHEN** пользователь открывает внешнюю библиотеку, в корне которой нет папки `plugins/`, а приложение поставляет плагин-источник
- **THEN** поставляемый плагин-источник загружается и доступен для распознавания и чтения внешней библиотеки

### Requirement: Изоляция плагинов

Плагин SHALL not иметь доступа к файловой системе и сети иначе как через явно объявленные и задокументированные host-функции, предоставляемые приложением. Приложение SHALL предоставлять плагинам-источникам host-функции файловой системы `fs_list_dir` и `fs_read_text`, работающие с путями относительно корня библиотеки и ограниченные песочницей: чтение SHALL быть разрешено строго внутри корня, запись SHALL быть запрещена, доступ к сети SHALL быть запрещён. Плагин, вызывающий host-функцию вне объявленного списка, SHALL не связываться при загрузке.

#### Scenario: Плагин выполняет действие расширения

- **WHEN** плагин вызывает только host-функции, объявленные в контракте
- **THEN** вызовы обрабатываются приложением, и плагин не получает прямого доступа к системе за пределами этих функций

#### Scenario: Чтение внутри корня библиотеки

- **WHEN** source-плагин вызывает `fs_list_dir` или `fs_read_text` с путём внутри корня библиотеки
- **THEN** приложение возвращает список содержимого директории или текст файла

#### Scenario: Попытка чтения за пределами корня

- **WHEN** source-плагин вызывает host-функцию файловой системы с путём, выходящим за пределы корня библиотеки
- **THEN** приложение отклоняет вызов с ошибкой и не раскрывает содержимое за пределами песочницы

## ADDED Requirements

### Requirement: Опрос source-плагинов

Приложение SHALL опрашивать загруженные source-плагины через экспортируемую функцию `invoke` с JSON-запросами действий `probe`, `scan` и `scan_book`. `probe` SHALL определять, является ли корень библиотеки источником, поддерживаемым плагином. `scan` SHALL возвращать полный список книг источника. `scan_book` SHALL возвращать данные книги по пути её папки для частичного пересканирования. Результаты SHALL передаваться приложению в виде структурированных данных книг.

#### Scenario: Распознавание источника

- **WHEN** приложение вызывает `probe` source-плагина для корня внешней библиотеки
- **THEN** плагин сообщает, поддерживает ли он данный корень

#### Scenario: Полное сканирование источника

- **WHEN** приложение вызывает `scan` source-плагина
- **THEN** плагин возвращает полный список книг источника с метаданными и файлами

#### Scenario: Частичное сканирование книги

- **WHEN** приложение вызывает `scan_book` с путём папки книги
- **THEN** плагин возвращает данные книги либо признак её отсутствия
