## Context

Сейчас рабочее место одно: ядро хранит `workspace.json` (`src-tauri/src/workspace_state.rs`), команды `get_workspace`/`save_workspace`, а `App.svelte` держит вкладки в памяти и дебаунсом сохраняет снимок. Стартовый раздел — библиотека; область рабочего места открывается кнопкой. Мотив и объём — в `proposal.md`, требования — в дельтах `specs/`. Здесь только технические решения.

## Goals / Non-Goals

**Goals:**

- Реестр рабочих мест с идентификатором, именем и вкладками; выбор активного.
- Хранение реестра ядром в служебном каталоге и однократный перенос `workspace.json`.
- Экран списка рабочих мест как стартовая область и переходы список ↔ рабочее место.
- Сохранение текущего поведения вкладок, чтения и переуказания книги.

**Non-Goals:**

- Экспорт/импорт рабочих мест, переносимость между машинами.
- Связь «библиотека ↔ рабочее место» многие ко многим.
- Базовый плагин-владелец реестра: в этом срезе хранение по-прежнему в ядре.
- Заметки, произвольный файл как вложение.

## Decisions

### Один файл реестра вместо каталога рабочих мест

Реестр хранится одним файлом `workspaces.json` в служебном каталоге:
`{ "workspaces": [ { "id", "name", "created_at_millis", "tabs", "active_tab_id" } ], "active_workspace_id" }`. Вкладки логически обособлены по объектам, но пишутся атомарно одним документом.

Альтернатива — каталог с файлом на рабочее место и отдельным индексом. Отклонена: данных мало (вкладок немного), нужна атомарность сразу нескольких изменений (создание + выбор активного), а лишние файлы усложняют запись. Разделение на файлы оправдано позже, когда реестр станет переносимым базовым плагином.

### Ядро хранит, оболочка оперирует

Ядро предоставляет только загрузку и сохранение реестра (`get_workspaces`/`save_workspaces`) с атомарной записью и переносом. Операции (создать, переименовать, удалить, выбрать, изменить вкладки) выполняет оболочка чистыми функциями и сохраняет результат дебаунсом — как сейчас устроены вкладки.

Альтернатива — отдельные команды ядра на каждую операцию (`workspace_create`, `workspace_rename`, …). Отклонена: дробит целостную модель, добавляет IPC и тесты без выгоды при одном писателе (оболочке). Границу можно поднять в ядро позже без смены формата.

### Перенос прежнего состояния — детерминированный и однократный

`load` реестра: если `workspaces.json` отсутствует, а `workspace.json` есть, ядро возвращает реестр с одним рабочим местом, вкладки которого взяты из прежнего файла; идентификатор рабочего места детерминирован (`"default"`), имя — «Рабочее место». Детерминированный идентификатор делает перенос идемпотентным даже до первой записи; после сохранения реестра прежний файл не используется и не удаляется.

Альтернатива — физически переименовать `workspace.json` при миграции. Отклонена: необратимая операция с риском потери при сбое; достаточно «мягкой» миграции чтением.

### Стартовая область — рабочее место

`workspaceOpen` при запуске `true`; если активного рабочего места нет, область показывает список рабочих мест. Библиотека остаётся полноценным разделом и открывается по своей кнопке.

Альтернатива — оставить старт на библиотеке. Отклонена: список рабочих мест — точка входа приложения (ROADMAP); иначе `workspace-manager` остаётся незаметной функцией.

### Экран списка — часть области рабочего места

Список рабочих мест — состояние области рабочего места (`WorkspacesPage.svelte`), а не отдельный раздел шапки. Когда активное рабочее место есть, показываются вкладки, а в панели вкладок слева есть элемент с именем рабочего места, возвращающий к списку. Кнопка-иконка рабочего места в шапке открывает область; повторное нажатие ведёт к списку, если активное рабочее место не выбрано.

Альтернатива — отдельная кнопка/раздел «Рабочие места» в шапке. Отклонена: список и рабочее место — одна сущность с двумя состояниями, а шапка уже насыщена.

### Книга открывается в активном рабочем месте

`workspace:open-book` добавляет вкладку в активное рабочее место; при его отсутствии — создаётся рабочее место по умолчанию и открывается. Переуказание недоступной книги по-прежнему подменяет книгу в конкретной вкладке.

Альтернатива — предлагать выбор рабочего места при открытии. Отклонена: лишний шаг; связь «библиотека ↔ рабочее место» многие ко многим проектируется отдельно.

### Идентификаторы и имена

Рабочее место получает идентификатор `ws-<base36 времени>-<счётчик>`, по образцу идентификаторов вкладок. Имя не обязано быть уникальным; пустое или состоящее из пробелов имя при переименовании отклоняется, при создании заменяется именем по умолчанию.

## Risks / Trade-offs

- **Стартовая область ломает существующие e2e, ожидающие библиотеку** → сценарии `shell.spec.ts` и родственные обновляются под старт с рабочего места.
- **Потеря вкладок при переносе** → перенос читающий и идемпотентный; прежний `workspace.json` не изменяется, есть Rust-тесты на перенос.
- **Расхождение модели ядра и оболочки** → обе стороны используют одинаковые поля (`tabs`, `active_tab_id`/`activeTabId`) и приведение значений на загрузке, как в `normalizeWorkspace`.
- **Смешение состояний рабочих мест при переключении** → вкладки адресуются идентификатором рабочего места; операции меняют только выбранное место, дебаунс пишет полный реестр.
- **Рост `App.svelte`** → операции реестра выносятся в `src/lib/workspace-registry.ts`, экран — в `WorkspacesPage.svelte`.

## Migration Plan

Изменение ЗАМЕНЯЕТ хранение: `get_workspace`/`save_workspace` и модуль одиночного состояния уступают реестру. Прежний `workspace.json` читается только для переноса и остаётся на диске. Откат — возврат прежних команд и модуля; файл реестра при этом не мешает.
