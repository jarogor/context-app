## Context

См. `proposal.md` — Why. Заметки хранятся в базовом плагине `notes-store`
(непрозрачная для ядра модель), клиент `src/features/notes/notes.ts` и панель
`NotesPanel.svelte` не интерпретируют хранилище глубже модели набора. Тип заметки
(`quote`/`text`/`shape`) уже сквозной. Отрисовку выполняет область содержимого:
встроенный `BookReader` (текучие текстовые форматы, EPUB) или плагин рабочего
места (страничные, PDF) через `WorkplaceContent`. Панель инструментов — общая
(`NoteToolbar.svelte`), её состояние живёт в `App.svelte`.

Проблема: в текучих форматах точка-якорь и геометрия заметок заданы в долях
раздела главы, а поток текста перестраивается при смене размера области и
масштаба — текст и заметки расходятся. Пагинация EPUB отклонена как изобретение
формата поверх EPUB.

## Goals / Non-Goals

**Goals:**
- В текучих форматах (EPUB и будущие подобные) оставить только заметки-цитаты:
  типы текст и фигура недоступны, не создаются и не отрисовываются.
- В страничных форматах (плагин, PDF) сохранить все три типа заметок.
- Дать заметкам всех типов пользовательские **название** и **комментарий** и
  редактировать их из панели заметок — они заменяют текстовую карточку там, где
  её нельзя стабильно разместить.
- Сделать имя заметки и поиск учитывающими название и комментарий.

**Non-Goals:**
- Пагинация EPUB и иная стабилизация потока текучих форматов.
- Изменение типов и поведения заметок в PDF (все три типа остаются).
- Миграция и совместимость уже сохранённых в EPUB заметок текст/фигура: релиза
  нет, они просто не показываются.
- Форматированный текст комментария (жирный, списки, ссылки) — только простой
  текст.
- Синхронизация названия/комментария с содержимым заметки (они независимы).

## Decisions

**Доступные типы заметок определяет режим чтения, а не формат сам по себе.**
Интерфейс чтения уже различает два режима: встроенное текстовое чтение
(`isSupportedFormat` → `BookContent` → `BookReader`) и плагин рабочего места
(`WorkplaceSelection` → `WorkplaceContent`). Первый — **текучий** (поток
перестраивается), второй — **страничный** (страницы фиксированы). Поэтому
доступные типы выводятся из режима: текучий → `['quote']`, страничный →
`['quote', 'text', 'shape']`. Новый текучий формат (FB2) автоматически получит
только цитаты, потому что подключается тем же встроенным путём. Альтернатива —
флаг в манифесте плагина или в контракте чтения: точнее для экзотических
случаев, но избыточна, пока текучесть совпадает с режимом чтения.

**Список заметок фильтруется на уровне приложения по режиму книги.** Ядро
(`notes-store`) не знает формата: `book_key` для него непрозрачен. Поэтому
отсеивать недоступные типы должен клиент. Приложение вычисляет доступные типы по
пути активной книги и передаёт в панель и в читалку уже отфильтрованный список
(`noteItems` и заметки для отрисовки). Это единственная точка отсечения: ни
`BookReader`, ни панель не показывают текст/фигуру в текучем формате, а данные в
хранилище не удаляются. Альтернатива — чистить хранилище: плагин не знает формат
книги и не может сделать это по режиму; к тому же удаление данных на чтении
неожиданно. Игнорирование эквивалентно удалению для пользователя и безопасно.

**Инструмент приводится к доступному типу при смене книги.** Если активным был
инструмент «фигура», а пользователь переключился на текучую книгу, панель
показывает только цитату. Приложение при смене доступных типов приводит
`noteTool.type` к `quote`, сохраняя цвет; `shape` — только для страничных. Так
скрытый инструмент не остаётся активным и не создаёт недоступную заметку.

**Название и комментарий — необязательные поля заметки любого типа.** Добавляются
в модель `Note`, вход `NoteInput` и патч `NotePatch` как `String` с
`#[serde(default)]`; версия состояния не поднимается, старые заметки читаются с
пустыми значениями. В патче поля — `Option<String>` (как `text`): отсутствие
означает «не менять», явная пустая строка — «очистить». Хранилище не
интерпретирует их содержимое. Альтернатива — слить комментарий с `text` карточки:
смешивает разные по смыслу поля и мешает страничным заметкам.

**Имя заметки: название впереди содержимого.** `noteName` сначала берёт
пользовательское название; при его отсутствии — прежний источник (цитата, текст,
подпись фигуры); при пустом содержимом — номер. Поиск (`filterNotes` и поиск в
панели) дополнительно смотрит в название и комментарий. Так названная человеком
заметка узнаётся по смыслу, а не по началу цитаты.

**Правка названия и комментария — в панели заметок.** Пункт «Изменить» в
контекстном меню заметки разворачивает в элементе списка форму из дизайн-системы
(`Input` + `Textarea`) с сохранением и отменой; после сохранения заметка
обновляется через операцию `update_note`. Форма живёт внутри элемента списка, а
не в модальном окне: правка быстрая, не мешает чтению и одинаково работает для
всех форматов. Комментарий показывается в элементе списка отдельной строкой при
наличии.

## Risks / Trade-offs

- **Расхождение режимов и форматов** → доступные типы выводятся из режима чтения
  (встроенное текстовое vs плагин), закреплено тестами `allowedNoteTypes`; новый
  текучий формат получает только цитаты по построению.
- **Скрытые заметки остаются в хранилище** → данные не теряются и не мешают;
  откат изменения возвращает показ без миграции.
- **Ограничение полноценных заметок в EPUB** → компенсируется названием и
  комментарием; выразительность без деформации потока.
- **Новые поля в хранилище** → необязательны и нормализуются; состояние прежних
  версий читается безопасно.
- **Смена инструмента при переключении вкладок** → инструмент приводится к
  доступному типу без сброса цвета; закреплено компонентным/браузерным сценарием.

## Migration Plan

Миграции данных нет: `title` и `comment` необязательны и по умолчанию пусты,
версия состояния не меняется. Заметки текст/фигура в текучих книгах не удаляются,
а просто не показываются. Откат — возврат показа всех типов и игнорирование новых
полей; записанные заметки не теряются.
