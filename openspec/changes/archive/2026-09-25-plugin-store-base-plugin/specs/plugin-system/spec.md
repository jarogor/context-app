## MODIFIED Requirements

### Requirement: Загрузка плагинов из локальной папки

Подсистема SHALL обнаруживать и загружать плагины из `plugins/` портируемой библиотеки, из пользовательского каталога плагинов приложения (общего для всех библиотек) и из поставляемых ресурсных директорий приложения. При совпадении имён приоритет SHALL быть таким: плагин библиотеки, затем плагин пользовательского каталога, затем поставляемый плагин. Для внешней библиотеки без собственной папки `plugins/` SHALL быть доступен поставляемый source-плагин. Загрузка SHALL не требовать сети, SHALL происходить при запуске и SHALL выбирать плагин по валидному манифесту и версии контракта.

#### Scenario: Внешняя библиотека использует поставляемый source-плагин

- **WHEN** пользователь открывает внешнюю директорию без собственного набора плагинов
- **THEN** приложение загружает поставляемый source-плагин и передаёт ему операции работы с этой директорией

#### Scenario: Плагин из библиотеки переопределяет ресурсный плагин

- **WHEN** в папке библиотеки и в ресурсах приложения присутствуют плагины с одним именем
- **THEN** runtime загружает только одну валидную версию согласно установленному приоритету и не выполняет источник дважды

#### Scenario: Плагин из пользовательского каталога переопределяет поставляемый

- **WHEN** установленный в пользовательский каталог плагин и поставляемый плагин имеют одно имя
- **THEN** runtime загружает плагин из пользовательского каталога и не загружает поставляемую версию

#### Scenario: Отсутствие подходящего source-плагина

- **WHEN** ни один загруженный source-плагин не подтверждает корень
- **THEN** приложение рассматривает директорию как портируемую или неподдерживаемую согласно существующему сценарию открытия и не выполняет библиотечно-специфичную логику в ядре

#### Scenario: Загрузка demo-плагина из папки plugins

- **WHEN** в папке `plugins/` присутствует корректный demo-плагин с манифестом и файлом `.wasm`
- **THEN** приложение загружает плагин в runtime и может вызвать его в точке расширения

#### Scenario: Отсутствие плагинов в папке

- **WHEN** папка `plugins/` пуста или не содержит корректных плагинов
- **THEN** приложение запускается без ошибки, а плагинная подсистема остаётся активной без загруженных плагинов

## ADDED Requirements

### Requirement: Привилегированные host-функции установки пакетов

Ядро SHALL предоставлять базовому плагину-стору привилегированные host-функции
инспекции, установки и удаления пакетов плагинов. Эти host-функции SHALL быть
доступны только плагинам, объявившим их в манифесте, и SHALL NOT давать прямого
доступа к произвольной файловой системе. Валидацию пакета и безопасную
распаковку SHALL выполнять ядро.

#### Scenario: Функции доступны только плагину-стору

- **WHEN** плагин, не объявивший привилегированные host-функции установки, пытается их вызвать
- **THEN** вызов отклоняется без выполнения операции

#### Scenario: Ядро валидирует пакет

- **WHEN** плагин-стор передаёт ядру архив пакета
- **THEN** ядро проверяет манифест, версию контракта и корректность путей до распаковки
