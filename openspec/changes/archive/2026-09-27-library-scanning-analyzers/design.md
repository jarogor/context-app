## Context

См. proposal.md — Why. Текущее состояние: `scanner.rs` обходит директорию, считая
книгой файл из широкого списка расширений, и различает файл/каталог эвристикой
«попробуй прочитать как каталог»; метаданные не извлекаются. Разбор EPUB уже есть
(`epub.rs`, через `zip` + `quick-xml`), но не используется. Обложка в каталоге —
это `ExternalFile` с путём; у внешней библиотеки книги — одиночные файлы, поэтому
сейчас обложек у них нет. Хост отдаёт `fs_list_dir` только имена, без типа записи.

## Goals / Non-Goals

**Goals:**

- Полный и корректный обход любой вложенности ровно для `pdf`, `djvu`, `epub`, `fb2`.
- Метаданные (название, авторы) и обложка — best-effort из содержимого, с фолбэками.
- Понятный дефолт: имя файла без расширения; автор неизвестен; картинка-заглушка.

**Non-Goals:**

- Полноценный рендер форматов (PDF/DjVu страницы), извлечение обложки из PDF/DjVu.
- Индексация содержимого, поиск по тексту.

## Decisions

### D1. Типизированное перечисление директории

Хостер `fs_list_dir` SHALL возвращать не только имена, но и тип записи:
`{ "name": ..., "kind": "file" | "dir" | "symlink" }` (тип — без следования по
ссылке). Сканер опирается на тип: `dir` — рекурсия, `file` — кандидат в книгу,
`symlink` — пропускается (защита от циклов и неоднозначности). Альтернатива
«эвристика через повторный `list_dir`» отвергнута: именно она даёт неполный и
непредсказуемый обход. Это изменение контракта; оба source-плагина (`library`,
`library-calibre`) обновляются и пересобираются.

### D2. Форматы и глубина

Книга — файл ровно с расширением `pdf`, `djvu`, `epub`, `fb2` (без учёта
регистра). Прочие файлы игнорируются. Глубина обхода не ограничивается
искусственно; завершаемость обеспечивается пропуском символических ссылок (D1) и
разумным страховочным пределом (глубина порядка нескольких десятков) на случай
аномальных структур. Скрытые элементы (имя с точки) пропускаются.

### D3. Анализаторы метаданных и обложки

Отдельные модули по форматам, работающие над `Fs::read_bytes`:

- `epub`: название/авторы из OPF (`dc:title`, `dc:creator`), обложка — из
  манифеста OPF (`cover-image`/`meta cover`); используется существующий разбор
  контейнера.
- `fb2`: название (`book-title`), авторы (`author`: first/middle/last/nickname),
  обложка — `coverpage` → `image`, встроенный `<binary>` (base64).
- `pdf`: название/авторы из метаданных документа (`/Info` и/или XMP) через
  крейт `lopdf`; обложка не извлекается.
- `djvu`: best-effort метаданные (структура DjVu ограничена; при неудаче —
  фолбэк); обложка не извлекается.

Ошибка разбора одного файла не прерывает сканирование остальных.

### D4. Фолбэки

Название — из содержимого, иначе имя файла без расширения. Авторы — из
содержимого, иначе пустой список (автор неизвестен). Обложка — из содержимого,
иначе её нет; интерфейс показывает картинку-заглушку.

### D5. Обложка как операция анализа, а не файл

Поскольку у внешней библиотеки книга — одиночный файл, обложка не является
отдельным файлом. Операция `cover(book_id)` SHALL анализировать файл книги и
возвращать извлечённую обложку (base64 + формат) либо признак отсутствия. Каталог
не обязан содержать файл обложки. Интерфейс запрашивает обложку для каждой книги и
при отсутствии показывает заглушку. Альтернатива «писать извлечённую обложку в
хранилище и отдавать путь» отвергнута: лишняя запись и рассинхронизация.

### D6. Изображение-заглушка

В дизайн-систему добавляется картинка-заглушка обложки, используемая, когда
обложка отсутствует (в `library-ui`).

## Risks / Trade-offs

- [Анализ метаданных читает файл целиком, это дорого для больших библиотек] →
  Метаданные извлекаются при сканировании и кэшируются в состоянии каталога;
  обложки — лениво, по запросу. При необходимости позже — частичное чтение.
- [DjVu-метаданные часто недоступны] → Best-effort; фолбэк на имя файла.
- [PDF-парсер увеличивает размер WASM] → Взвесить; при недопустимом размере —
  минимальный собственный разбор `/Info`.
- [Изменение `fs_list_dir` ломает оба source-плагина] → Оба обновляются и
  пересобираются в рамках изменения; доки контракта актуализируются.

## Migration Plan

1. Изменить `fs_list_dir` на типизированные записи и обновить хостер/доки.
2. Переписать сканер и добавить тесты с фикстурой.
3. Добавить анализаторы форматов и фолбэки.
4. Перевести `cover` на анализ по `book_id`.
5. Добавить заглушку обложки в UI.
6. Пересобрать плагины, прогнать проверки.

## Open Questions

- Нужен ли отдельный крейт для PDF или хватит минимального разбора `/Info`.
