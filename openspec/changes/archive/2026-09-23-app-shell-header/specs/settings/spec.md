## MODIFIED Requirements

### Requirement: UI настроек

Система SHALL предоставлять UI настроек отдельным frontend-плагином: страница со списком секций отображается в контентной области каркаса, а точка входа — кнопка настроек в верхней панели каркаса. Для каждого поля секции UI SHALL отображать человекочитаемое название и типизированный контрол: флажок для `boolean`, текстовое поле для `string`, числовое поле для `number`, выбор для `select` и текстовое поле JSON для `json`. Оболочка SHALL предоставлять верхнюю панель и контентную область и SHALL not содержать кода секций настроек.

#### Scenario: Кнопка открывает страницу настроек

- **WHEN** пользователь нажимает кнопку настроек в верхней панели
- **THEN** в контентной области отображается страница настроек со списком секций

#### Scenario: Возврат с главной страницы

- **WHEN** пользователь закрывает настройки через кнопку верхней панели
- **THEN** в контентной области снова отображается основной frontend-плагин

#### Scenario: Список секций

- **WHEN** страница настроек открыта
- **THEN** SHALL быть показаны все зарегистрированные секции с заголовком, описанием владельца и полями с человекочитаемыми названиями

#### Scenario: Редактирование значений как JSON

- **WHEN** поле секции имеет тип `json`
- **THEN** оно редактируется как JSON, а при некорректном JSON SHALL быть показана ошибка без сохранения

#### Scenario: Типизированные контролы полей

- **WHEN** секция содержит поля разных типов
- **THEN** каждое поле отображается контролом своего типа, а сохранение секции передаёт значения соответствующих типов

#### Scenario: Оболочка без UI настроек

- **WHEN** frontend-плагин настроек не загружен
- **THEN** каркас SHALL продолжать работать, а кнопка настроек оставаться доступной
