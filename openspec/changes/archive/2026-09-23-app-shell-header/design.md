## Context

См. `proposal.md` — Why. Текущее состояние: `App.svelte` позиционирует регион настроек как `position: fixed` в правом верхнем углу поверх `library-ui`, а `settings-ui` сам управляет состоянием `button`/`page` через layout-сообщения. `PluginFrame` жёстко задаёт высоту iframe `100vh`.

## Goals / Non-Goals

**Goals:**

- Явный каркас: верхняя панель с названием раздела и кнопкой настроек, контентная область строго ниже.
- Состояние «настройки открыты» принадлежит оболочке, а не frontend-плагину.
- Состояние основного плагина (библиотеки) сохраняется при переключении.
- Плагины не могут перекрывать каркас.

**Non-Goals:**

- Слоты каркаса для произвольных кнопок плагинов — пока только кнопка настроек.
- Динамический реестр frontend-плагинов и полноценная навигация/роутинг.
- Изменение логики source-плагина библиотеки.

## Decisions

### 1. Состояние настроек во владении оболочки

`App.svelte` держит `settingsOpen: boolean`; кнопка в верхней панели переключает его. `settings-ui` больше не рисует кнопку и не шлёт layout-сообщения: плагин рендерит только страницу. Это устраняет цикл пересоздания iframe, который возник бы, если состояние принадлежало плагину, а оболочка перемещала его между регионами.

Альтернатива — оставить кнопку в плагине и перемещать iframe — отклонена: пересоздание iframe сбрасывает состояние и зацикливает layout-протокол.

### 2. Оба frontend-плагина смонтированы постоянно

Контентная область содержит два `PluginFrame` (библиотека и настройки); неактивный скрывается через `display: none`. Так состояние библиотеки (открытая библиотека, список, поиск) не теряется при переходе в настройки и обратно.

Альтернатива — условный рендер `{#if settingsOpen}` — отклонена из-за потери состояния библиотеки при каждом переключении.

### 3. Фиксированный каркас и высота iframe

Верхняя панель — `position: fixed` высотой `--header-height` (48px) с `z-index` выше региона уведомлений. Регион уведомлений и контентная область начинаются ниже панели (`top: 48px`). `PluginFrame` получает высоту `100%` вместо `100vh`, чтобы заполнять явно заданную высоту родителя.

### 4. Название раздела в панели

Заголовок раздела переносится из `library-ui` в верхнюю панель: «Библиотека» или «Настройки» в зависимости от `settingsOpen`. В `Library.svelte` удаляется `<h1>Библиотека</h1>`; строка с бейджем источника и кнопкой «Открыть библиотеку» сохраняется.

## Risks / Trade-offs

- [Постоянно смонтированный `settings-ui` держит iframe в DOM] → нагрузка минимальна; при необходимости позже перейти на lazy mount.
- [`display: none` для iframe может приостанавливать часть внутренних таймеров] → не критично для текущих плагинов.
- [Заголовок раздела дублируется, если плагин рисует свой] → у `library-ui` заголовок удаляется; другие плагины появятся позже.

## Migration Plan

1. Обновить `App.svelte` (панель, состояние, две панели контента) и `PluginFrame` (высота).
2. Упростить `settings-ui` (только страница, без кнопки и layout).
3. Убрать заголовок из `library-ui`.
4. Пересобрать frontend-плагины, обновить спеку `app-shell` и `settings`, выполнить проверки.
