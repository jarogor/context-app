## Context

Служебные файлы приложения разбросаны по коду: константы имён лежат в
`constants.rs`, `workspace_state.rs`, `library_history.rs`, `plugin/activation.rs`,
`plugin/wasm_cache.rs`, состояние базовых плагинов — по их исходникам
(`src-wasm-plugins/*/src/lib.rs`, ключи `settings.json`, `notes.json`,
`stores.json`). Спека `plugin-system` описывает только `plugin-manifest.json` и
кэш компиляции в общем виде; остальное не зафиксировано. Вопрос «почему всё JSON,
а кэш — TOML» возникает именно из-за этого: формат кэша задан не нами.

## Goals / Non-Goals

**Goals:**

- Одна спека, перечисляющая служебные конфиги и кеши, их расположение и формат.
- Явно объяснить исключение TOML для `wasm-cache.toml` и закрепить правило
  «JSON — по умолчанию».
- Описать состояние базовых плагинов и SQLite-индекс.

**Non-Goals:**

- Изменение самих файлов или их форматов — фиксируется текущее поведение.
- Миграции форматов; версионирование уже описано в спеках-владельцах
  (`workspace-manager`, `library-history`, `notes-store`, `settings`).

## Decisions

### D1. `wasm-cache.toml` остаётся TOML

Формат нельзя сменить на JSON: Extism 1.30 при `with_cache_config(path)` вызывает
`wasmtime::Cache::from_file`, а wasmtime 43 читает конфигурацию только через
`toml::from_str::<Config>` (`wasmtime-internal-cache`). `Config` реализует
`serde::Deserialize`, но загрузка из файла привязана к TOML. Поэтому правило —
«наши реестры JSON; конфиг кэша задан wasmtime и потому TOML» — фиксируется в
спеке, а не конвертируется.

### D2. JSON — единый формат реестров приложения

`workspaces.json`, `workspace.json`, `disabled-plugins.json`,
`library-history.json`, `app-config.json` и состояние базовых плагинов — JSON:
один парсер, читаемость, согласованность с обменом данными плагинов.

### D3. Расположение по сборке

Каталог состояния: `dev_data/app-state` в разработке, каталог данных приложения
в выпуске; состояние базовых плагинов — `dev_data/base-plugins`. Пользовательский
каталог плагинов — `dev_data/app-plugins`. Всё под `.gitignore`.

### D4. Спека — источник истины, `_docs` — справка

Формальные требования заводятся в `openspec/specs/app-state`; в
`_docs/structure.md` добавляется краткая ссылка на разбор «JSON против TOML».

## Risks / Trade-offs

- [Дублирование с `_docs`] → `_docs` — локальная справка, не источник истины;
  спека выверяется отдельно.
- [Спека может разойтись с кодом] → константы имён уже покрыты тестами
  модулей-владельцев; спека ссылается на их расположение.

## Migration Plan

Кода не меняем. Порядок: спека `app-state` (расположение, форматы, TOML-исключение)
→ добавление требования о состоянии плагина в `plugin-system` → ссылка в `_docs`.
Откат — удаление спеки.

## Open Questions

- Нужна ли общая версия формата служебных файлов (сейчас версия есть только у
  состояния базовых плагинов: `skills`-версии в `notes-store`), — отдельное
  решение.
