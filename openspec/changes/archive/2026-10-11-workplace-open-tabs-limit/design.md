## Context

Лимит открытых вкладок — ограничение на число одновременно открытых вкладок
рабочего места. Сейчас вкладки открываются без предела: каждая держит
смонтированную книгу, поэтому неограниченный рост числа вкладок — риск
непредсказуемых последствий. См. proposal.md — Why.

Значение настройки принадлежит секции настроек приложения `app.general`
(`src-tauri/src/plugin/app_host.rs`, `APP_SETTINGS_SCHEMA`). Ядро уже читает
собственные значения секции через помощники `app_setting_*` и отдаёт их
оболочке отдельными Tauri-командами (`theme_preference`, `reader_theme`),
которые ждут общий `Mutex<AppState>` и потому асинхронны. Оболочка получает
значения на стадии начальной загрузки (`src/features/lifecycle/bootstrap.ts`) и
передаёт их областям.

Панель вкладок — `src/features/workplace/WorkplaceTabs.svelte`; кнопки открытия
«Добавить книгу» и «Открыть файл с диска» плюс операция дублирования — три
точки, создающие вкладку. Операции над составом вкладок живут в
`src/features/workplace/workplace.ts` (`openBook`, `duplicateTab`).

## Goals / Non-Goals

**Goals:**

- Единый настраиваемый лимит открытых вкладок со значением по умолчанию 50.
- Блокировка создания вкладок при достижении лимита с понятной подсказкой.
- Сохранение сверхлимитных вкладок при уменьшении лимита с явным выделением
  превышения и пояснением в журнале уведомлений.
- Применение нового лимита без перезапуска.

**Non-Goals:**

- Автоматическое закрытие вкладок при уменьшении лимита (запрещено требованием).
- Изменение состава/порядка вкладок, реестра рабочих мест и форматов хранения.
- Отдельный «жёсткий» верхний предел поверх пользовательского (достаточно
  предупреждения в описании поля).
- Счётчик открытых вкладок в других областях (шапка и т.п.).

## Decisions

**1. Значение лимита — поле собственной секции приложения.** Ключ
`window.open_tabs_limit` (тип `number`, значение по умолчанию `50`) добавляется
в `APP_SETTINGS_SCHEMA` рядом с прочими значениями приложения. Пользователь
управляет лимитом в существующем разделе настроек; отдельного хранилища не
заводим.

- Альтернатива: хранить лимит в реестре рабочих мест — отклонена: лимит общий
  для приложения, а не свойство отдельного рабочего места.

**2. Чтение лимита — отдельная Tauri-команда по образцу `theme_preference`.**
`window_open_tabs_limit` (асинхронная, через `State<Mutex<AppState>>`) возвращает
число. Оболочка читает его на бутстрапе и передаёт в область рабочего места
пропом; изменение секции `app.general` (событие `settings:changed`) обновляет
значение без перезапуска.

- Альтернатива: тянуть значение из общего портфеля «состояния приложения» —
  избыточно; точечная команда повторяет уже принятый в проекте образец.

**3. Лимит проверяется в операциях состава вкладок.** Функция открытия получает
лимит и при его достижении возвращает состояние без изменений. Так правило
живёт в одной чистой точке и покрывается модульным тестом, а область лишь
отражает доступность действий.

- Альтернатива: проверять только в UI — оставляет открытым путь через
  клавиатуру/программный вызов и дублирует условие в нескольких местах.

**4. Три состояния кнопок открытия.** `доступно` (вкладок меньше лимита),
`лимит достигнут` (равно лимиту) — заблокировано, обычная краткая подсказка о
лимите; `превышен` (вкладок больше лимита) — заблокировано, выделение превышения
(отличимая обводка/фон кнопок создания вкладки, включая кнопку дублирования) и
краткая подсказка о превышении. Подсказка одинакова для всех трёх кнопок и не
содержит подробностей — они уходят в уведомление. Выделение превышения SHALL
исчезать при возврате в предел.

- Недоступная кнопка не получает событий указателя, поэтому подсказка
  выставляется обёртке кнопки, а не самой кнопке: иначе при наведении на
  `disabled`-кнопку подсказка не показывается.

**5. Пояснение о превышении — в журнал уведомлений.** При переходе в состояние
превышения публикуется пользовательское уведомление с двумя вариантами действия
(закрыть лишние вкладки либо увеличить лимит). Публикация дедуплицируется: пока
превышение сохраняется, повторные записи не публикуются — только при повторном
возникновении превышения.

## Risks / Trade-offs

- **[Дедупликация уведомлений при частой смене лимита]** → хранить булев признак
  «превышение уже сообщено» в состоянии области и сбрасывать при возврате в
  предел.
- **[Лимит 50 по умолчанию может быть избыточен на слабых машинах]** →
  пользователь управляет значением сам; предупреждение в описании поля
  информирует о риске большого значения.
- **[Значение настройки может прийти нечисловым/нулевым]** → читающая сторона
  нормализует значение (не меньше 1), отсутствие провайдера настроек даёт
  значение по умолчанию 50.

## Migration Plan

Чисто аддитивное изменение: новое поле настройки получает значение по умолчанию
без миграции данных. Откат — удаление поля и проверок лимита.
