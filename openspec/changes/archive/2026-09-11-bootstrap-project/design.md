# design.md

## Context

Greenfield-проект: в репозитории нет кода, только OpenSpec-разметка (`.opencode/`, `openspec/`). Стек зафиксирован: Rust-ядро + Svelte + Tauri 2 (desktop), SQLite через `rusqlite`, плагины — Extism (WASM). Мотивация и объём изменения описаны в proposal.md; требования — в соответствующих spec-файлах.

## Goals / Non-Goals

**Goals:**
- Работающий десктопный каркас Tauri 2 + Svelte, собираемый и запускаемый локально.
- Портируемая структура директории библиотеки и схема БД, на которой строятся дальнейшие итерации.
- Сквозной путь «импорт EPUB → запись в БД → список в UI → открытие в read-view».
- Загрузка одного demo-WASM-плагина через Extism из локальной папки `plugins/`.

**Non-Goals:**
- Мобильные сборки (iOS/Android), установка плагинов по сети, UI управления плагинами, другие форматы книг, синхронизация.

## Decisions

### 01. Структура портируемой директории библиотеки

```
library/
  library.db      # SQLite-база
  books/          # файлы книг (один файл формата на запись)
  covers/         # обложки (jpg/png, именуются по book_id)
  plugins/        # плагины: каждая папка = манифест + .wasm
```

Почему: единая самодостаточная директория — основной нефункциональный контракт. Альтернатива (хранилище вне библиотеки) отвергнута: нарушает портируемость.

### 02. Схема БД

Таблицы: `books`, `authors`, `series`, `tags`, `files`, и связующие `book_authors`, `book_series`, `book_tags`.

- `books`: `id INTEGER PK`, `title TEXT`, `uuid TEXT`, `created_at`, `updated_at`.
- `authors` / `series` / `tags`: `id`, `name` (уникальный).
- `files`: `id`, `book_id FK`, `kind TEXT` (`book` | `cover`), `path TEXT` (относительный), `format TEXT`.
- `book_authors` / `book_series` / `book_tags`: FK-пары; `book_series` дополнительно хранит `series_index`.

Все пути в `files` — относительные к корню библиотеки; движок БД — `rusqlite` с миграциями через встроенный versioning (пользовательская таблица `schema_version`).

### 03. Импорт EPUB

Импорт выполняется на Rust-стороне: файл копируется в `books/` с уникальным именем, EPUB парсится для извлечения title, авторов (OPF-метаданные) и обложки (извлекается и сохраняется в `covers/`). В сценарии без метаданных title берётся из имени файла. Имя файла в `books/` формируется с префиксом `book_id`, что гарантирует уникальность (требование spec). Парсер — крейт `epub` (`zip` + `quick-xml` под капотом); при повреждённом файле возвращается ошибка и транзакция откатывается.

### 04. Слои приложения (Rust)

- `library/` — портируемая директория: открытие, валидация структуры, открытие `rusqlite::Connection`.
- `catalog/` — CRUD записей каталога через слои репозиториев поверх `library`.
- `import/` — импорт книг (EPUB-парсер, копирование файлов).
- `plugins/` — Extism host: обнаружение плагинов в `plugins/`, загрузка в Extism runtime.
- Tauri commands — тонкие обёртки (IPC) над этими слоями; данные в UI передаются как JSON.

Vertical slice: каждая команда Tauri при необходимости проходит свой слайс «command → сервис → репозиторий», без избыточного уровня абстракции.

### 05. Extension point контракт (MVP)

Контракт плагина (версия `1`):
- Экспортируемая функция плагина: `invoke(input_json: string) -> string` — точка расширения для произвольных событий приложения.
- Host-функции контракта: `log(message: string)` — протоколирование через приложение (модуль `extism:host/user`).
- Манифест плагина (JSON, `plugin-manifest.json` в папке плагина): поля `contract_version`, `name`, `description`, `module` (путь к `.wasm`), `export`, `host_functions`.

Расширение контракта (FS/сеть через прокси-хоста) — будущие changes; изоляция уже обеспечивается WASM-runtime и отсутствием необъявленных host-функций. При загрузке плагин, не экспортирующий `invoke`, отбраковывается с ошибкой; остальная система продолжает работать.

### 06. UI (Svelte)

Минимальный фронтенд: страница «Библиотека» (список книг с обложками) и страница «Чтение» (read-view с текстом). Передача данных — через типизированные Tauri-commands. Read-view на MVP — простой текст извлечённого содержимого; полноценный рендеринг EPUB — будущие итерации.

## Risks / Trade-offs

- [Extism-интеграция с Rust-мобильными таргетами может потребовать адаптации] → Мобильные сборки явно вне scope этого изменения; подсистема проектируется так, чтобы рантайм был отделён слоем интерфейса.
- [Извлечение метаданных EPUB из неустойчивых/полукорректных файлов может давать пропуски] → Дефолты: title из имени файла, пустые списки авторов; повторные парсинги при импорте новых форматов не затронут существующую схему.
- [WASM-плагины в Extism и версии контракта могут «просесть» на практике] → Контракт версионируется и документируется; демо-плагин живёт в репозитории как опорный артефакт.
- [WebView-рендеринг реальных EPUB слишком сложен для MVP read-view] → На MVP выводится извлечённый текст; улучшенный рендер — отдельный change, не влияющий на спецификацию каталога.

## Migration Plan

Greenfield: достаточно корректной инициализации структуры библиотеки и БД при первом открытии; миграции БД — встроенный механизм версий `schema_version`, начиная с версии 1.

## Open Questions

- Точный набор host-функций контракта расширится вместе с реальными плагинами; это не влияет на спецификацию и задачи данного change.
