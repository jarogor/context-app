## Context

`WorkplaceSurface.svelte` рендерит только активную вкладку: блок `{#if tab}` с
`{#key `${tab.id}:${tab.path}`}`. При смене активной вкладки прежний `ReaderPage`
размонтируется, следующий создаётся заново, `ReaderPage.onMount` вызывает
`load(path)` — книга читается ядром повторно, документ EPUB собирается и
перерисовывается, позиция восстанавливается.

Альтернативный, более простой путь — кешировать данные книги и позицию и
пересоздавать вкладку без сетевого чтения. Он не устраняет пере-рендер: PDF
заново растеризует canvas, EPUB — пересобирает документ, подсветки и опорную
строку. Поэтому выбран вариант «держать вкладки смонтированными».

## Goals / Non-Goals

**Goals:**

- Убрать перезагрузку книги при переключении вкладок: переключение — только показ
  уже открытого содержимого.
- Сохранить состояние каждой вкладки (позиция, масштаб, страница, выделение) без
  повторного восстановления.
- Не менять модель реестра вкладок и сохраняемое состояние (`tab.position`,
  `tab.zoom`) — совместимость с персистентностью сохраняется.

**Non-Goals:**

- Ограничение памяти по числу открытых вкладок (LRU-выгрузка) — отдельный шаг.
- Пересмотр сохранения позиции/масштаба в реестре рабочих мест.
- Ленивое монтирование «спящих» вкладок (задел на будущее при большом числе
  открытых книг).

## Decisions

### D1. Все вкладки смонтированы, активная показывается

`WorkplaceSurface` рендерит по компоненту вкладки на каждую открытую книгу.
Активная получает класс `flex`, остальные — `hidden`. Скрытие через CSS, а не
условием `{#if}`: компонент и его iframe/документ продолжают существовать.
`ReaderPage` прежний интерфейс не меняет.

### D2. Отдельный компонент вкладки для адресации читалок

Переход к заметке (`App` → `WorkplaceSurface.goto`) должен попадать в активную
вкладку. `bind:this` не принимает выражение `Map.get`, поэтому вкладку оборачивает
тонкий `WorkplaceTabPage.svelte`: он монтирует `ReaderPage`, хранит ссылку на
читалку и регистрирует её в карте `WorkplaceSurface` по идентификатору вкладки
через `onReader`. При размонтировании регистрация снимается.

### D3. Заметки — по книге вкладки

`WorkplaceSurface` строит карту заметок по вкладкам: активной вкладке отдаются
заметки активной книги, остальным — пустой список. Скрытые вкладки не показывают
подсветки до активации; при активации получают заметки своей книги.

### D4. `visible` только для активной вкладки

Флаг `visible` (показ поверхности рабочего места) передаётся в `ReaderPage`
только активной вкладке, чтобы скрытые вкладки не сообщали о прокрутке и не
конкурировали за состояние.

### D5. Память — осознанная плата

Каждый открытый документ (EPUB-iframe, PDF-canvas) остаётся в памяти до закрытия
вкладки. Для одного-двух десятков текстовых книг это несущественно; для тяжёлых
PDF — заметно. Ограничение памяти (выгрузка давно неактивных вкладок) выносится в
отдельное изменение; сейчас важно убрать раздражающую перезагрузку.

## Risks / Trade-offs

- [Рост памяти с числом вкладок] → Осознанно (D5); ограничение — отдельный шаг.
- [Тесты, адресующие единственный iframe чтения] → Обновлены: документ активной
  вкладки берётся через `[data-testid="workplace-tab-page"][data-active="true"]`.
- [Скрытые iframe продолжают исполнять `$effect`/таймеры] → `visible` передаётся
  только активной; `BookReader` игнорирует отчёт о прокрутке, когда невидим.

## Migration Plan

Состояние реестра и формат `workspaces.json` не меняются — откат сводится к
возврату рендера одной активной вкладки. Порядок: вынести компонент вкладки →
перейти на `{#each}` с классом видимости → заметки по вкладкам и карта читалок →
обновить e2e → документация.

## Open Questions

- Нужна ли выгрузка давно неактивных вкладок (ограничение памяти) — отдельное
  решение по мере роста числа открытых книг.
