# plugin-system Specification

## Purpose

Скелет плагинной подсистемы на основе WASM и Extism host runtime: контракт extension point(ов), изолированная загрузка плагинов из локальной папки `plugins/` и демонстрация загрузки одного demo-плагина без сети и без управления плагинами из UI.

## Requirements

### Requirement: Контракт extension point(ов)

Подсистема SHALL определять контракт extension point(ов) — явно объявленный набор host-функций и ожидаемых экспортируемых функций плагина, с которыми плагины могут взаимодействовать. Контракт SHALL быть стабильной точкой расширения приложения и документироваться.

#### Scenario: Плагин, соответствующий контракту

- **WHEN** плагин экспортирует функции, ожидаемые контрактом, и использует только объявленные host-функции
- **THEN** плагин успешно загружается и может быть вызван в точке расширения приложения

#### Scenario: Плагин с несоответствующим контракту

- **WHEN** плагин не предоставляет ожидаемых контрактом экспортируемых функций
- **THEN** приложение отклоняет загрузку плагина с сообщением об ошибке, не нарушая работу остальных плагинов

### Requirement: Загрузка плагинов из локальной папки

Подсистема SHALL сканировать папку `plugins/` портируемой директории, обнаруживать плагины по их манифесту и загружать их с помощью Extism host runtime. Загрузка плагинов SHALL не требовать доступа к сети и SHALL происходить при запуске приложения.

#### Scenario: Загрузка demo-плагина из папки plugins

- **WHEN** в папке `plugins/` присутствует корректный demo-плагин с манифестом и файлом `.wasm`
- **THEN** приложение загружает плагин в Extism runtime и может вызвать его в точке расширения

#### Scenario: Отсутствие плагинов в папке

- **WHEN** папка `plugins/` пуста или не содержит корректных плагинов
- **THEN** приложение запускается без ошибок, плагинная подсистема остаётся активной, но загруженных плагинов нет

### Requirement: Изоляция плагинов

Плагин SHALL не иметь доступа к файловой системе и сети иначе как через явно экспортированные host-функции, предоставляемые приложением и применяющие ограничения доступа.

#### Scenario: Плагин выполняет действие расширения

- **WHEN** плагин вызывает только host-функции, объявленные в контракте
- **THEN** вызовы обрабатываются приложением, и плагин не получает прямого доступа к системе за пределами этих функций
