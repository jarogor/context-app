# Обновления приложения

Обновления разделены по границе каркаса и приложения:

- **Ядро** — исполняемый файл приложения и каркасные плагины
  (`src-tauri/resources/base-plugins`: настройки, уведомления, стор). Оно
  обновляется **одним пакетом из одного источника**: заменить ядро по частям
  нельзя, потому что каркасные плагины и приложение связаны контрактом.
- **Прикладные плагины** — источники книг, заметки, форматы чтения и
  расширения. Они обновляются **по отдельности** через стор плагинов из любых
  подключённых источников. Пользовательская копия плагина с тем же
  идентификатором перекрывает поставляемую.

Источник обновлений приложения — одно из мест, добавленных в настройках на
странице «Обновления». Приложение и плагины обновляются из всех добавленных мест;
по умолчанию есть встроенный адрес: в разработке `dev_data/updates` в корне
проекта, в выпуске `https://updates.jarogor.ru/context` (переопределяется при
сборке переменной `CONTEXT_UPDATE_URL`). В поле ввода по умолчанию принимается
адрес в интернете, папку можно выбрать отдельной кнопкой. Опытные пользователи
могут задать источник переменной окружения `CONTEXT_UPDATE_SOURCE` в формате
`file:/путь` или `network:https://адрес`.

## Источник

Файловый источник — каталог; сетевой — базовый адрес. В обоих случаях в корне
лежит `update-index.json`:

```json
{
  "contract_version": 1,
  "core": {
    "version": "0.2.0",
    "notes": "Что изменилось",
    "platforms": {
      "linux-x86_64": {
        "mode": "appimage",
        "location": "Context_0.2.0_amd64.AppImage",
        "sha256": "<hex>"
      },
      "windows-x86_64": {
        "mode": "installer",
        "location": "Context_0.2.0_x64-setup.exe",
        "sha256": "<hex>"
      },
      "darwin-aarch64": {
        "mode": "portable",
        "location": "Context_0.2.0_aarch64.zip",
        "sha256": "<hex>"
      }
    }
  }
}
```

Ключ платформы — `ОС-архитектура` (`linux`, `windows`, `darwin`; `x86_64`,
`aarch64`, `i686`, `armv7`). Для сетевого источника `sha256` обязательна; для
файлового проверяется, если указана. Сетевой источник должен использовать HTTPS;
HTTP разрешён только для локальной разработки (`localhost`, `127.0.0.1`).

## Способы установки ядра

- `portable` — zip-архив, содержимое которого **накладывается на каталог
  установки** (рядом с исполняемым файлом; на macOS — корень `.app`). Пакет
  должен содержать исполняемый файл, `resources/base-plugins` и остальные
  ресурсы поставки. Старое содержимое каталога заменяется целиком.
- `appimage` — готовый AppImage; заменяет текущий файл `$APPIMAGE`.
- `installer` — штатный установщик платформы (NSIS/MSI и т.п.), запускаемый
  после выхода приложения.

После подготовки обновления приложение завершается, помощник ждёт выхода,
применяет пакет и запускает новую версию. Журнал применения лежит в
`app-state/updates/<версия>-<режим>/apply.log`.

## Плагины

Индекс стора плагинов — `store-index.json`:

```json
{
  "packages": [
    {
      "id": "d3b8f2a1-6c4e-4f7a-9b2d-1e5c8a7f0b3d",
      "name": "format-pdf",
      "version": "0.2.0",
      "kind": "format",
      "description": "Чтение PDF",
      "location": "format-pdf-0.2.0.zip",
      "sha256": "<hex>"
    }
  ]
}
```

Стор сравнивает версию пакета с версией установленного или поставляемого
плагина и предлагает обновление. Установка заменяет каталог плагина целиком,
не затрагивая служебное состояние плагина (оно хранится отдельно). Для
сетевого стора `sha256` обязательна.
